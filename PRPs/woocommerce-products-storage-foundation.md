# WooCommerce storage foundation (local acceptance only)

Scope: six new tables, no external requests, routes, scheduler, notifications, export, or production deployment. Owner instructed to build tables after discussing storage. Final formal PR review remains required.

Authority: WooCommerce observed product response -> sanitized RAW -> DIM; preserve observed source timestamps and currency; null is unknown, not zero. Existing dim_walmart_listings is authoritative for source identity; exact account/store/item composite, never infer identity from SKU. New-system owned brand and submission configs; external submission ID is a string, distinct from source store ID. Store options currently expose store_id only: resolve source_account_ref before saving, reject ambiguous selection. Reuse sys_woocommerce_stores UUID, no duplicate credentials. No default seed/config is enabled. Price markup is a configuration for genuine sale pricing, never proof of a reference price. Stock configured quantity requires verified sellable inventory. No periodic cloning. 60-day submission interval retained as inactive configuration, not executed. No notification recipients or batches until later approved scope.

RAW must redact secrets, passwords and unapproved plugin metadata before insertion; retain observed payload and hash, including repeated observations across sync runs. DIM carries current response fields; image count derived from array (unknown vs empty). Confirm publication date from evidence; creation date is not first publish date. Mapping only records verified relation; optional initial raw pointer is observed evidence, not inferred historical data. Do not alter existing Walmart strike price or new-product scores. Listing management and new products read via scoped service using composite identity; no direct RAW queries. All IDs preserve strings except WooCommerce native numeric ID. UTC timestamptz, numeric(18,4), currency code required with price. Historical rule versions append, one current version per brand/global setting; existing submission config updates must be audited via existing config audit on future API. No auto-enabling.
