# PRP：财务 · 日记账接入飞书审批单 V1

- 状态：已批准（rocky 2026-11-05，协调者代批），分支 fin/journal-approvals，PR #316；11-05 变更一节对应 PR #317。
- 数据源决策：`docs/data-sources/decisions/finance-feishu-approval-sync-decision.md`，结论：飞书只读同步，`SOURCE_SYNC`。
- 前置：`PRPs/finance-journal-backend-v1.md`（#312）。本 PRP 补上它不做的「审批单同步」和「自动挂单」。

## 1. 目标

财务在日记账页面点「同步审批单」，把飞书的资金类审批单拉进系统。系统把能唯一对上的单挂到流水上，对不上的列候选让财务选；挂上的单参与分类，并报出差额和「审批单无付款流水」两类异常。

## 2. 范围

做：

1. 四类审批单：费用报销、付款申请、备用金申请、备用金核销。审批定义编码从环境变量 `FINANCE_APPROVAL_CODES` 读取，不进仓库；没配置或缺一类时，同步失败并返回错误码 `SYNC_FEISHU_APPROVAL_CODES_NOT_CONFIGURED`，不静默跳过。
2. 只读接口：取应用 token、审批实例列表（GET）、审批实例详情。不调任何飞书写接口，也不调通讯录接口。
3. 手动同步：日记账页面一个按钮，走任务中心的运行记录、分步记录和状态。已有一次在跑就不重复开。定时默认关闭。
4. 同步窗口：最近 90 天，切成每段不超过 30 天。已结束超过 14 天且取过详情的单不再取详情。
5. 自动挂单，在每次同步结束和流水导入后各跑一次，可重复执行：
   - 流水摘要或备注写了系统里有的、没取消的单号：直接挂。
   - 金额相等（差不超过 0.011）、都是人民币、流水日期在审批通过前 3 天到通过后 45 天内、收款人对得上，并且流水和单一一唯一：自动挂。单子没写收款人时，唯一也算。
   - 其余列为候选。审批中的单只进候选，不自动挂。
   - 已初审或终审的流水不动；财务摘掉过的「流水 + 单号」组合不再自动挂回去。
6. 分类优先级：人工 > 审批单 > 规则。表单写明类别的算「审批单」，压过规则；表单没有类别时用事由和明细跑规则，只补空白类别，标「审批单(规则)」。一笔挂多张单时，类别一致才用。
7. 两类异常：
   - 审批单差额：审批金额和流水金额对不上，初审要写差额说明。
   - 审批单无付款流水：流水起始月及以后发起、已同意、没有任何流水挂这张单。

不做：

- 定时同步和任务中心配置页。
- 下载、保存附件原件和截图。
- 调飞书写接口，或把系统里的状态写回飞书。
- 美元单自动挂单。
- 新权限点、角色和数据范围。
- 汇率来源改造。

## 3. 存储

新表 `std_finance_feishu_approvals`（迁移 `20261105_0077_finance_approvals`）。主键是飞书实例编码，单号唯一。

| 类别 | 字段 |
|---|---|
| 单据 | 单号、审批定义编码、类型、飞书状态、发起 / 完成 / 办理时间 |
| 申请人 | 飞书 user_id、部门 ID |
| 内容 | 事由、金额、币种、付款方式、是否开票、费用类别、关联单号、费用明细 |
| 收款 | 收款人、收款银行、账号尾号 |
| 过程 | 附件元数据、审批记录、评论 |
| 同步 | 最近一次运行 ID、取回时间 |

- 收款账号只存尾号，完整账号在解析时丢掉。
- 不存附件和截图的下载链接，只存来源、名称、是否图片、属于第几条明细。
- 表里不存姓名。

## 4. 申请人姓名

读取时用 `app_users.feishu_user_id` 匹配系统员工表，优先 `feishu_name`，其次 `display_name`；匹配不到显示编号。不用 `feishu_open_id`，因为它每个飞书应用都不一样。审批记录和评论里的人同样处理。

## 5. 接口（前缀 `/api/finance/cashflow`）

- `GET /approvals`：审批单列表，带已付流水和付款状态。
- `GET /approvals/sync`：最近一次同步的状态。
- `POST /approvals/sync`：手动同步，返回 202。
- `GET /lines` 增加 `approval_candidates`。

## 6. 权限

全部接口只有超级管理员（`require_super_admin`），不新增权限点。

## 7. 任务中心改动

- `gov_integration_interfaces.method` 的约束从只允许 POST 改为允许 POST 和 GET，因为飞书审批列表是 GET。
- `execution.py` 增加分派：provider 为 `feishu` 且 handler 匹配时，交给财务审批单同步。
- `service.py` 的 `productlist_only` 判断放行财务审批单。
- `catalog.py` 增加登记方法，配套脚本 `scripts/bootstrap_finance_approval_governance.py`：幂等；接口和配置打开，定时关闭；已有配置不覆盖。

## 8. 配置

| 变量 | 说明 |
|---|---|
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | 飞书应用，和后端其他飞书功能共用 |
| `FINANCE_APPROVAL_CODES` | 四类审批定义编码，格式 `费用报销=…,付款申请=…,备用金申请=…,备用金核销=…`。真实值不进仓库 |
| `FINANCE_APPROVAL_EXCLUDED_DEPARTMENT_IDS` | 逗号分隔的部门 ID，这些部门的审批单不进报销闭环。真实值不进仓库 |

## 9. 回滚边界

- 迁移 0077 回退时，审批单表有数据就拒绝；接口表里有非 POST 的行也拒绝，要先人工处理。
- 自动挂单写在 `manual_finance_cash_line_state.refs`，事件表留 `auto_attach_ref` 记录（actor=system），财务可以逐笔摘掉。
- 同步只写审批单表和运行记录，不改流水本身。同步失败时，已经写入的单保留，可以再同步一次。
- 停用：在任务中心关闭这条配置，按钮返回未配置错误，页面其他功能不受影响。

## 10. 上线

首次生产同步在上线后进行，每步需 rocky 书面授权：

1. 跑迁移。
2. 配置 `FINANCE_APPROVAL_CODES` 和 `FINANCE_APPROVAL_EXCLUDED_DEPARTMENT_IDS`。
3. 跑登记脚本。
4. 首次点「同步审批单」并核对结果。

## 11. 验收

- 同步、自动挂单、候选、摘单在本地预览上走通（回放本地已有拉数结果，不连飞书）。
- 后端测试只用合成数据，飞书客户端用假实现，不发网络请求。
- 仓库文件和测试里没有真实账号、户名、部门、人名、审批定义编码和密钥。
