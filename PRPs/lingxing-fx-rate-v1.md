# PRP：领星月汇率统一（V1）

状态：rocky 2026-11-05 批准方案，分两个 PR。决定见 `docs/data-sources/decisions/lingxing-fx-rate-source-decision.md`。

## 问题

新系统没有领星汇率表和同步。日记账读产品定价规则里的 `usd_cny_rate`，定价和日销还有写死的 6.6 兜底，汇率来源不统一。

## PR-1（本 PR）

- 新表 `fact_lingxing_fx_rate`：月份 + 币种一行，存 `my_rate`、`rate_org`、币种名、领星更新时间、来源（`sync` / `seed`）、原始响应引用。
- 任务中心同步 `lingxingFxRate`：接口和配置默认关闭，打开后可手动触发，也每周一上海时间 02:00 自动跑（rocky 2026-11-05 定；领星的月汇率会在月后不固定的日子被人改，最多晚一周同步到）；从当月（上海时间）往回拉 13 个月，一个月一次请求；原始响应先落原始层，再按月份 + 币种写入。
- 同步规则：某月没有数据跳过；所有月都没有算失败；任何一个月报错或数据不合格，这次算失败，不把半截结果当成功。已写入的月份保留，重跑覆盖。`my_rate`、`rate_org` 为空或 0 存空。
- 公共读取函数 `app/modules/fx_rates/reader.py`，全系统读汇率只走它。
- 日记账改读它：业务日所在月的 USD `my_rate`；没有就是空，页面显示「—」，不兜底。
- 部署导入 `fx_rates` 节：只补没有的月份和币种，不覆盖同步数据。部署文件不进仓库。
- 治理脚本 `backend/scripts/bootstrap_fx_governance.py`：只登记，全部默认关闭。`backend/scripts/enable_fx_sync.py`：授权后打开手动同步和每周定时，重复执行不改已有定时。
- 任务中心「立即同步」按钮放行本接口（后端原来只放行指定接口）。任务中心页面按接口自动列出。
- 只读接口 `GET /api/finance/cashflow/fx-rates`（超管，只列 USD）。
- 页面手动同步（rocky 2026-11-05）：`GET`、`POST /api/finance/cashflow/fx-rates/sync`（超管），复用任务中心同步任务，已在跑不重复开。页面对比同步前后的美元月汇率，提示新增、更新、未变各几条，一页一个完整年份。
- 前端另提一个 PR（后端 PR 不改前端）：新增 财务 → 财务设置 → 资金 汇率 页面，列 月份、币种（USD→CNY）、月汇率、来源（领星·月汇率（我的汇率）），只读；任务中心把这个同步归到财务分组。
- 不新增权限点；不动定价、日销、WFS、结算利润。

## 上线顺序

1. 跑迁移。2. 导入部署文件里的汇率种子，日记账立刻有 2026-09 至 2026-11 的汇率。3. 跑治理脚本登记同步。4. rocky 授权后跑 `backend/scripts/enable_fx_sync.py` 打开同步和每周定时（脚本本身不发请求，之后定时会自动调领星），再在任务中心点「立即同步」跑一次。

## PR-2（另开，本 PR 不做）

产品定价、日销利润、WFS、结算利润 V2 改读公共函数；删除写死的 6.6；不再读写 `usd_cny_rate`（字段留作历史）；用开关默认走旧逻辑，先用重算预览出差异报告，rocky 签字后统一切换并重算历史。规则见决定文档。

## 验收

合成数据测试覆盖：解析单层响应、月份不符和数字不合格判失败、空月跳过、全空失败、重跑覆盖、同步覆盖种子、种子不覆盖、原始响应落库、默认关闭、任务中心调度到本同步、日记账只读同月 USD `my_rate` 且不兜底。
