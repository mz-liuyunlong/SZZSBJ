## 二、关键口径实现确认

- 负责人：dim_product_owner(active, 最新 effective_date, 按 item_id) → 兜底 dim_product.owner（标注"商品表"）→ 未分配（排行黄色高亮，不丢行）
- 公司卡片 = 负责人排行合计（同一份数据求和，销售额/广告费天然一致）
- 成本：仅 source_system='lingxing_api'，采购/头程/配送费三字段分别取非空最新；匹配键 store+item+msku → 回退 item+msku；不回退飞书
- 毛利 = 销售额 − (采购+头程)×销量/汇率 − WFS费×销量 − 佣金 − 广告费；佣金沿用现有店铺规则（12%/15%），platform_fee 仅参考字段；悦斯CS 固定成本规则与旧利润明细一致
- 汇率/佣金率：环境变量 `LX_EXCHANGE_RATE` / `LX_COMMISSION_RATE_DEFAULT` / `LX_COMMISSION_RATE_SPECIAL` 可覆盖，默认 6.6 / 0.12 / 0.15（与现有生产逻辑一致）
- 广告：ItemID 级聚合 ad_spend/total_sales/orders，不分摊到 MSKU；明细里单独一张"广告表现(ItemID级)"表；有广告无销售的 item 计入负责人聚合
- 库存：≤date_to 最新 snapshot_date 快照；库存天数 = available_stock ÷ 近 min(60,实际数据天数) 天日均销量
- 默认日期 = MAX(stat_date)，页面显示"数据日期"，不默认今天/昨天
- 异常六类，null(未配置)/0(配置为0) 分列统计，范围=筛选期内有销售或有广告的商品
- 退款不扣销售额，refund_amount 明细单独展示

## 三、部署步骤（白名单 scp，禁止整目录 rsync）

```bash
# 1. 上传 4 个文件（本地 → 线上）
scp "src/services/salesDashboardService.ts"      company-ai:/opt/lingxing-auto/src/services/
scp "src/lingxingSalesRoutes.ts"                 company-ai:/opt/lingxing-auto/src/
scp "admin-frontend/src/SalesDashboard.tsx"      company-ai:/opt/lingxing-auto/admin-frontend/src/
scp "admin-frontend/src/App.tsx"                 company-ai:/opt/lingxing-auto/admin-frontend/src/

# 上传前先备份线上被覆盖的 2 个文件：
ssh company-ai "cd /opt/lingxing-auto && cp src/lingxingSalesRoutes.ts src/lingxingSalesRoutes.ts.bak.\$(date +%Y%m%d_%H%M%S) && cp admin-frontend/src/App.tsx admin-frontend/src/App.tsx.bak.\$(date +%Y%m%d_%H%M%S)"

# 2. 线上构建前端（后端是 ts-node 启动，无需编译）
ssh company-ai "cd /opt/lingxing-auto/admin-frontend && npm run build"

# 3. 重启服务
ssh company-ai "systemctl restart lingxing-admin.service && systemctl status lingxing-admin.service --no-pager | head -5"
```

回滚：用 .bak 文件覆盖回去 + 重新 build + 重启即可；新增的 2 个文件删除不影响旧功能。

## 五、验收标准

1. 页面地址：`/admin/#/sales-dashboard`（旧页 `/admin/#/lingxing-sales-data` 保留可用）
2. 首页导航按钮显示"销售驾驶舱"，旧明细页可从驾驶舱"明细数据"按钮进入
3. 不带日期打开，"数据日期"自动显示 2026-07-01（最新有数据日），页面不空、不报错
4. 负责人排行包含"未分配"（黄色行）
5. 卡片销售额 = 排行销售额合计；卡片广告花费 = 排行广告花费合计（含未分配）
6. 以 2026-06-30 单日验证异常区量级（已于 2026-07-03 用对比 SQL 复核确认）：
   有销售但SKU空 = 2；有广告但SKU空 = 5；缺采购 = 2；缺头程 = 2；缺WFS配送费 = 9；广告>0销售=0 = 84
   ⚠️ 早期核查给出的 238/247/247/403 是错误基准，勿再使用。成因：
   - 238 = 当日全部有广告花费的 item 数（严格 store+item+msku JOIN 遇广告表 msku 空全部失配）
   - 403 ≈ 严格 store JOIN 失配（feishu 配送费记录 1859 条 store_id 全空）+ 未过滤 source_system
   - 拍板口径（lingxing_api 来源 + item_id+msku 回退匹配）下的真实值即本行数字
7. 点击负责人行出现产品明细（MSKU 级）+ 广告表现（ItemID 级）两张表
8. 异常区"查看明细"能过滤出对应异常商品，未配置显示"未配置"、0 显示"0（异常）"
9. 旧页面回归：/walmart-ads、/walmart-ads-data、/feishu-raw-sales-data、旧明细页 5 个 Tab 均正常
10. 需重启：lingxing-admin.service（后端 ts-node 加载新路由 + 前端静态产物更新）
