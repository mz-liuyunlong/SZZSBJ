## 七、工作纪律与协作惯例（本项目的生存法则）

1. **铁律**（PROJECT_CONTEXT 有全文）：改前核查真实代码/表结构禁止臆测；
   不可覆盖人工记录；外部数据必先入RAW；密钥走环境变量；
   前端/GPT只读DIM/FACT层
2. **任务流程**：只读核查 → 回传实施计划+SQL → 等确认 → 备份(.bak.时间戳) →
   实施 → typecheck(本地+生产) → 部署 → 验收(含下游回归) → 更新context → 最终报告
3. **写库纪律**：任何数据写入前 dry-run + reports/ 留CSV白名单
   （审计+回滚依据）；建表/改列 SQL 必须先回传等人工确认
4. **验收文化**：每个结论附证据（SQL数字/文件行号）；边界场景专项抽验；
   下游回归固定项——launch_date非空数(基线1502)、product_name非空(1354)、
   旧广告接口 /query/ads_keyword_lookup row_count=1、20:15/20:30任务正常
5. **终端约定**：含中文的逻辑一律走文件上传，命令行只发纯ASCII短命令
   （终端链路对中文/引号/超长行不可靠，历史上连续翻车四次）
6. **人工字段清单**（任何同步/ETL/计算任务禁止写入）：
   dim_product.owner / launch_date(只补空) / manual_lifecycle_* /
   product_management_status* / dim_product_cost_config人工成本 /
   biz_operation_daily_log 的人工三列（任务G后生效）
7. **cron 变更**：只允许追加或注释，禁止删除行；新任务必须核对
   PIPELINE_MAP 的时间依赖链（上游数据就绪时间）
