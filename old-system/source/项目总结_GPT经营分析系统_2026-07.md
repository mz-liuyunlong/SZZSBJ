# 项目总结：Custom GPT × 公司广告/经营数据库对接（2026-07）

## 一、成果概览

从"Custom GPT 调用公司 API 报 ClientResponseError、服务器零日志"这一个问题出发，最终交付了一套完整的 AI 经营分析系统：

1. **两个稳定可用的 Custom GPT**
   - 「Ads广告分析工具」：自然语言查询 Walmart 广告关键词数据（authCheck + adsKeywordLookup）
   - 「运营经营分析助手」：全员可用的经营分析工具，按负责人/店铺/ItemID/MSKU/时间范围输出优秀产品、问题产品和可执行动作
2. **一条跨境网络链路**：绕开境内服务器对海外 HTTPS 的拦截
3. **一个经营分析 API**（/api/ops/analyze）：真实 DIM/FACT 聚合 + 产品分类 + 行级动作建议
4. **一条利润数据管道**：raw_feishu_table → fact_profit_daily 每日自动回填

## 二、系统架构（当前生产状态）

```
Custom GPT (ChatGPT)
  ↓ Bearer Token
https://gpt-api.giginana.com   ← 海外中转 38.244.59.150 (CentOS 7.9)
  ↓ Nginx (HTTPS, Let's Encrypt)     locations: /ads-ai-api/, /auth-check, /api/, /privacy.html
127.0.0.1:18090
  ↓ SSH 反向隧道 (systemd: gpt-api-tunnel, 自动重连)
国内腾讯云服务器 127.0.0.1:8090
  ↓ ads-ai-api (FastAPI, /opt/ads-ai-api/main.py)
MySQL walmart_ai_data (只读账号 ads_ai_reader)
  ← fact_profit_daily 由利润 ETL 每日 19:30 回填 (写账号 ads_etl_writer)
  ← 上游 lingxing-auto 每日 18:30 生成 order_profit_daily (T-2)
```

安全状态：8090/MySQL 不对公网开放；18090 仅监听 127.0.0.1；Token 走环境变量；
API 全只读白名单模板；ETL 写账号仅有 fact_profit_daily 的 INSERT/UPDATE；日志不记 Token。

## 三、关键问题与解决记录

| # | 问题 | 根因 | 解决 |
|---|------|------|------|
| 1 | GPT 报 ClientResponseError，Nginx 零日志 | OpenAI 出口(Azure IP)→腾讯云境内 HTTPS 链路被 RST，非 GPT 配置问题（Schema/认证均正常） | 海外中转 + SSH 反向隧道 + systemd 持久化 |
| 2 | analyzeOperationData 报 403/404 | /api/ops/analyze 后端不存在 + 中转无 /api/ 转发；GPT Builder 的 403 提示为误导 | Phase 1 固定 JSON 接口 + Nginx 加 /api/ location |
| 3 | ResponseTooLargeError | 无过滤场景响应 114KB 超 OpenAI ~100KB 限制（10分类×50条×21字段+未取整小数+跨类重复） | 无过滤仅返回公司汇总；产品对象瘦身；分类截断+去重；80KB保险丝 → 2KB |
| 4 | ACOS=0% 误导 | ad_sales=0 时 SQL 返回 0 | acos=null + acos_status 三态语义 |
| 5 | 补货/停补建议冲突 | 断货(库存≤5)与周转慢(销量≤3)条件重叠 | SQL 层互斥(≤5 vs >30) + 行级动作生成 |
| 6 | fact_profit_daily 空表 | 利润生产线终点是飞书快照(raw_feishu_table)，FACT 层从未接线；分层错位：派生指标写进 RAW 命名表 | 利润 ETL v1：RAW→FACT 回填 + 每日 cron |
| 7 | ETL 写入报 net_profit cannot be null | 表约束 NOT NULL DEFAULT 0 与"不伪装净利"口径冲突 | 脚本适配：5列不写入由默认0生效，口径存 extra_json（不 ALTER 共享表） |
| 8 | 服务器命令中文/引号/长行反复损坏 | 用户终端传输链路编码不可靠 | 约定：含中文的逻辑一律走文件上传；命令行只发纯 ASCII 短命令 |

## 四、利润口径（重要，团队共识）

**运营端毛利，已扣广告费**（非财务口径）：
毛利润 = 销售额 − 广告费 − WFS配送费×销量 − 平台佣金 − (采购成本+头程成本)×销量/汇率
- 飞书"毛利润（$）" → fact_profit_daily.gross_profit；"毛利率" → profit_rate
- net_profit/refund_amount/成本分项：v1 不填（DB 默认 0，非真实值），口径标注在 extra_json
- 退款暂不含（refund_included=false）
- GPT 分类"毛利率低于10%"与运营口径一致

## 七、运维要点

- **证书续期**：gpt-api.giginana.com 证书 90 天有效，确认 certbot 自动续期：`systemctl list-timers | grep certbot`
- **隧道监控**：`systemctl status gpt-api-tunnel`，restart 次数异常增多需排查
- **每日 ETL**：19:30 cron，日志 /opt/ads-ai-api/scripts/profit_etl.log；验证 `MAX(stat_date)` 每日前进
- **ETL 抽样核对**：`python3 build_fact_profit_daily_from_raw_feishu.py --verify`
- **回滚**：API 代码有带时间戳的 .bak 备份；ETL 数据按 `source_system='raw_feishu_order_profit_daily'` + 日期范围删除（先 COUNT 预览，管理员执行）
- **改动纪律**：main.py 的 Phase 2 段整段替换式迭代（OPS_RANGE_TYPES 行至文件尾），旧广告接口区（前 ~370 行）不动
