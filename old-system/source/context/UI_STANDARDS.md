# UI_STANDARDS.md — 前端统一规范（列表/台账页）

> 目的：把反复被"每次修补"的界面格式固化为**全站标准**，新页面照做、旧页面逐步归一，避免每页各造一份。
> 适用：admin-frontend 所有"列表/台账/数据表"类页面（feishu-raw 各Tab、清货、绩效、PMC、月度、经营分析、花名册 等）。
> 建档：2026-07-27（起因：多页顶部工具条格式不一致、"同步 -" 未接、帮助图标各自为政）。

---

## 1. 标准顶部工具条（每个列表页必须有）

统一形态（左元信息 + 右图标组），**一律复用 `admin-frontend/src/LxToolbar.tsx`，禁止各页自造图标/样式**。

左侧元信息（一行，灰色小字，右对齐于筛选区）：

```
共 <N> 行 · 同步 <YYYY-MM-DD HH:mm> · 第 <P>/<T> 页
```

- `共 N 行`：当前口径总行数（筛选后全量，不是本页条数）。
- `同步 <时间>`：数据最近同步时间，取该页数据源返回的 `latest_sync_time`（或等价字段）。
  **⚠️ 硬规则：不允许显示 "同步 -"。** 出现 "-" = 后端没返回同步时间或前端没接 = 缺陷，必须补齐（后端返回 latest_sync_time，前端格式化 `toLocaleString("zh-CN",{month,day,hour,minute})`）。
- `第 P/T 页`：当前页/总页数。

右侧图标组（顺序固定，全部来自 LxToolbar，`lxTB.iconBtn` 样式）：

| 图标 | 组件 | 行为 |
| --- | --- | --- |
| 刷新 | `IconRefresh` | 重新拉取当前页数据 |
| 帮助 | `IconHelp` | **壳内**进入该页帮助（见 §2） |
| 下载 | `IconDownload` | 导出当前筛选口径 CSV（有下载权限门禁的走既有校验） |
| 列配置 | `IconColumns` | 打开列显示/固定/排序配置（有表格列配置的页才放） |

样板实现：`FeishuRawSalesData.tsx` 第 2118–2127 行的元信息条 + 图标组；共享样式/图标在 `LxToolbar.tsx`。

- **禁止用本页局部样式覆盖 `lxTB.iconBtn`**（2026-08-16 补，实证：`AiFinanceCredits.tsx` / `AiFinanceItemCashProfitV2.tsx` 各自定义了一份 `iconBtnWrap`，写成 `{...lxTB.iconBtn, ...iconBtnWrap}` 后展开，把公共件的 `border:none`/`padding` 盖掉，等于绕过本节"禁止各页自造"）。确需改图标钮外观 → **改 `LxToolbar.tsx` 公共件**，不在各页套壳。

## 2. 帮助图标 = 壳内直达该页帮助（不开新标签）

- 每个页面注册自己的 `page_key`，帮助文章存 `dim_page_help`（HelpCenter 读取）。
- 点帮助 `?` → 进入 `#/help?page=<page_key>`，**在当前外壳内切换**，不得 `window.open(..., "_blank")` 开新标签跳出壳。
  - 正确：`onNavigate?.("help")` 或 `window.location.hash = "#/help?page=<key>"`（由外壳路由渲染 HelpCenter，并 `?page=` 定位到该文）。
  - 错误（历史遗留，待改）：`window.open("#/help?page=xxx", "_blank")`。
- page_key ↔ Tab 映射集中在各页的 `PAGE_HELP_KEYS`（见 FeishuRawSalesData）。新页新增 page_key 时，必须在 `dim_page_help` 建对应文章（group_name 归到该页所属板块，如"运营中心/AI人力/广告系统"）。

---

- **「前往该功能 →」按钮（2026-08-12 立规）**：由 `dim_page_help.target_url` 驱动，HelpCenter 在文章标题旁渲染紫色跳转按钮。**每篇帮助文必须填 target_url**，取值规则：
  - 壳内原生页 → `shell:<页面key>`（如 `shell:pmc-wfs-fee`，HelpCenter 解析前缀后走 onNavigate 壳内切换，不刷新）；
  - iframe/外部页 → 直接填 URL（HelpCenter 内置 :8081→meeting、:3456→llm、/walmart-ads-data→ads:all 等映射，未命中映射的整页跳转）；
  - 不填 target_url = 按钮不显示 = 不合格（2026-08-12 pmc-wfs-fee 补齐案例）。

## 4. 落地做法（迁移一页的清单）

1. 引入 `import { lxTB, IconRefresh, IconHelp, IconDownload, IconColumns } from "./LxToolbar";`（删本地自造图标）。
2. 元信息条按 §1 格式渲染（total / latest_sync_time / page / totalPages）。
3. 后端该页列表接口返回 `latest_sync_time`（源：该数据源 dim/fact 的 sync 元信息或 raw 的 data_date/synced_at）。
4. 帮助 `?` → 壳内 `#/help?page=<key>`；`dim_page_help` 建/核对该 page_key 文章。
5. 记入 TASK_CHANGE_LOG。

## 5. 列宽可拖动（每个表格页必须有）

所有"数据表/列表"页的表头列，**必须支持鼠标拖拽列头右边缘调整列宽**，并配套「列宽重置」按钮。参照样板：:3000 广告页 与 `FeishuRawSalesData`（已实现 `colWidths` / `resizeRef` / 列头右缘 7px `col-resize` 把手，会话内生效）。

标准要素（三样齐全才算合规）：
1. **拖拽把手（必须肉眼可见 · Google 风格）**：每个列头右边缘一条 `cursor: col-resize` 的窄条（≈9px），`onMouseDown` 记 `{tab,col,startX,startW}`，`mousemove` 改该列 `width=max(60, startW+dx)`。宽度按 `colWidths[tab][col]` 存（会话内；如需持久化再议）。
   - ⚠️ **透明把手不合规**：把手必须常显——一条浅灰竖条（`#dadce0`，约列高 56%），鼠标悬停变 Google 蓝（`#1a73e8`）加粗至全高。样板：`FeishuRawSalesData` 的 `.lx-colresize` CSS（`::after` 常显灰条 + `:hover::after` 变蓝），用 className 而非透明 inline style。
2. **「列宽重置」按钮**：放右侧工具区（挨着「列配置」），点击清空该页/该Tab的 `colWidths`，恢复默认列宽。
3. **提示文案**：工具区一行浅色小字，如「拖列头右缘调列宽 · 点表头排序（▼▲↕）· 点单元格高亮行列」，让用户知道可拖（否则把手不明显、以为没做）。

> **实现约束（2026-08-16 补，不改变"三样齐全"的合规判定）**：用固定 `style` id 注入 CSS 时，**同 id 必须同内容**。
> 实证事故：`AiFinanceCredits.tsx` 与 `AiFinanceItemCashProfitV2.tsx` 都用 id `lx-colresize-css`，内容却不同，且都写成"已存在则跳过"——
> 结果谁先挂载谁生效：v2 先挂 → credits 的把手退化成透明条（违 §5 第85行）；credits 先挂 → v2 整段 CSS 被跳过、连 ⓘ 气泡样式一起丢失。
> 规范：列宽把手 CSS 用 id `lx-colresize-css`（内容以第85行灰条版为准），表头 ⓘ 气泡 CSS 另用 id `lxfin-tip-css`，两者内容全站逐字一致。

现状（2026-07-27）：
- FeishuRawSalesData 各Tab（含 产品管理）：拖拽把手 ✅、可见化(Google灰条+悬停蓝) ✅、「列宽重置」按钮 ✅、提示文案(按钮 title) ✅ → 已达标。
- :3000 广告页：三样齐全（外部应用，作参照，不改）。
- 其余新表格页：一律照本标准做（拖拽把手 + 列宽重置 + 提示）。

> 规则：新增表格页 = §1 工具条 + §2 帮助壳内 + §5 列宽可拖动（三选一都不能少）。

## 6. 顶部 KPI 卡可隐藏（有 KPI 卡的页必须支持）

任何在顶部放 KPI/统计卡片行的列表/看板页，**必须提供"隐藏/显示 KPI"开关**，让用户按需收起顶部占位、把纵向空间让给数据表。

标准要素：
1. **开关入口**：放右侧图标组（`§1` 工具条内，挨着刷新/列配置），一个 `iconBtn`（如 ▤），`title="隐藏 / 显示 顶部KPI"`。
2. **行为**：点击切换整行 KPI 卡的显示/隐藏（`display:none` 或等价 class 切换）；隐藏后数据表上移。
3. **状态**：会话内内存态即可（`useState`）；如需跨会话记忆再议，**禁用 localStorage/sessionStorage**（沿用全站约定）。

现状（2026-08-01 立规）：新增/改造带 KPI 的页（PMC 库存一览表等）一律照此做；旧页逐步补。

> 规则更新：新增带 KPI 的表格页 = §1 工具条 + §2 帮助壳内 + §5 列宽可拖动 + §6 KPI 可隐藏。

## 8. 总计行 + 翻页（列表/台账页必须有；2026-08-03 需求方定稿，样例=订单利润 Beta）

任何"数据表/列表/台账"页，**必须同时具备①底部吸底总计行 ②翻页控件**。样板=订单利润 Beta（`FeishuRawSalesData`），一律照此统一，禁止各页自造样式。

### 8.1 总计行（tfoot 吸底）
- 位置：表格 `<tfoot>` 一行，`position:sticky; bottom:0` 吸底常显。
- 样式（逐字照样板）：`background:#eef2ff; fontWeight:700; color:#3730a3; borderTop:2px solid #c7d2fe`。
- 首列文案：`总计（N行）`（N=**当前筛选全量**记录数，分组页可用 `总计（N 商品）`）。
- 口径：**当前筛选的全量集合**求和，**不是只当前页**（关键——翻页不改总计）。数值列显示各自合计，非数值列留空。

### 8.2 翻页控件
- 每页档位：`PAGE_SIZE_OPTIONS = [50, 100, 200]`，默认 50；切换档位时 `setPage(1)`。
- 控件顺序：`每页 [50][100][200] · 首页 · 上一页 · [页码窗口最多5个] · 下一页 · 末页 · 共 N 条 · 跳至 [输入框] 页`。
- 页码窗口：`start = max(1, min(page-2, totalPages-4))`，渲染 `min(5,totalPages)` 个；当前页高亮。
- 首页/上一页 在 `page<=1` 禁用；下一页/末页 在 `page>=totalPages` 禁用；跳至输入框 Enter 且 `1<=v<=totalPages` 才跳。
- 按钮样式=样板 `s.pageBtn(active,disabled)`：`padding:5px 12px; borderRadius:5px; border:1px solid #e5e7eb; background:active?#6366f1:#fff; color:active?#fff:#374151; fontWeight:active?700:400; fontSize:13px`。
- 分页单位：平表按行分页；**分组/可展开表按"组"分页**（整组连同子行为一页单元），`totalPages=ceil(组数/pageSize)`。
- 筛选/排序/每页变化时 `setPage(1)`；`totalPages` 缩小时把 `page` 夹到范围内。

### 8.0 表头吸顶 + 总计吸底（滚动容器内两头固定）
- 表格放在带 `maxHeight + overflow:auto` 的滚动容器里时，**列表头 `<thead> th` 必须 `position:sticky; top:0`（配 `zIndex` 压过滚动体、底部 `box-shadow` 描边），滚动时固定在容器顶部**；总计行 `<tfoot>` `position:sticky; bottom:0` 吸底。两头都固定，中间行滚动。
- 反例（不合规）：只做总计吸底、表头随行滚走 → 滚下去看不到列名。

### 8.3 元信息条补「第 P/T 页」
- §1 元信息条格式统一为：`共 N 行 · 同步 <时间> · 第 P/T 页`（分组页可 `共 N 商品 · M 行 · 同步 <时间> · 第 P/T 页`）。

现状（2026-08-03 立规）：订单利润 Beta 已达标（作样板）；PMC 库存一览表照此补齐；其余新表格页一律照做，旧页逐步补。

> 规则汇总更新：新增带 KPI 的列表/台账页 = §1 工具条 + §2 帮助壳内 + §5 列宽可拖动 + §6 KPI 可隐藏 + §8 总计行+翻页。

## 9. 每个TAB/页面必须有独立URL后缀（hash路由；2026-08-11 需求方定稿）

**要求**：所有新增TAB/页面必须有自己的独立URL后缀，能直接打开、能收藏、能粘贴分享——形如
`http://42.193.254.170/admin/#/help`、`/admin/#/attendance` 这样的hash路由地址。
禁止做成"只能点侧边栏切进去、地址栏不变"的无地址页面。

- 主控台（admin-frontend App.tsx）：新页面一律注册hash路由（初始化读取 `window.location.hash`
  → currentPage，切换时写回 hash），模块内子tab用二级后缀（如 `#/finance/tools`、`#/finance/credits`）。
- 独立服务前端（如 asin-kw-mvp :3000）：新页面一律独立path（如 `/walmart-sem`），同样可直达。
- 命名：全小写，连字符分词，语义化英文（`#/finance/item-cash-profit`），不用拼音不用缩写黑话。
- **老TAB逐步迁移**（需求方2026-08-11拍板"慢慢迁移"）：不专门立项，日后凡改到某个老页面，
  顺带给它补hash路由；老的无地址入口保留不删（禁删原有功能），新老地址并存。
  已达标存量：#/help、#/attendance、#/hr-performance、#/business-analysis、#/sales-dashboard、
  #/feishu-raw-sales-data、#/lingxing-sales-data、#/pmc/wfs-fee（2026-08-12）、#/profit/order-v2（2026-08-18 订单利润V2）。

## 10. 帮助文内容标准（2026-08-12 需求方定稿：不只写操作，规则/取值必须写清）

每篇 `dim_page_help` 文章必须包含以下六节（顺序可调，缺一不合格）：

1. **这是什么**：一句话说清版块解决什么问题（有真实案例/战果的带上）。
2. **判定/计算规则**：页面每个判定与数字的公式、阈值、粒度、排除项（如"实收>人工即立案，店铺×MSKU粒度，CS排除"）。
3. **取值口径**：每个字段的数据来源——哪张表/哪个系统、怎么算出来的、多久刷新一次（如"实收费率=Walmart结算逐单配对折算近60天众数，每周一刷新"）。用户看完能回答"这个数是哪来的"。
4. **操作流程与状态**：状态流转图/清单、每个状态谁能做什么操作、审批规则。
5. **纪律与考核**：必填项、频率要求、扣绩效规则（分值/触发条件）。
6. **FAQ/边界情形**：为什么某产品不在列表、为什么数字会变、常见误解——把运营会来问的问题提前写掉。

> 配套既有制度：帮助文章变更走「帮助中心同步规约」（文章+notify_overview时间轴+context 三同步）；页面注册 page_key 走 §2。

## 11. 列配置（领星式；2026-08-16 需求方拍板，升格为规范）

> 来源：本规格此前只散落在 TASK_CHANGE_LOG 的施工记录里（2026-07-16 `:1252-1253`、2026-07-21 `:1514-1516`、`:1274`、2026-07-17 `:1280-1283`），
> 不是规范条文。2026-08-16 需求方指定「AI财务页照广告系统那套来」，正式升格。仓库内样板 = `FeishuRawSalesData.tsx:2272-2345`（弹窗）+ `:1996-2023`（固定列偏移）+ `:2523`（总计行同步吸左）。
> 注：广告系统 `#/ads/*` 是 iframe 嵌 `:3000 walmart-ads-data` 独立应用（`App.tsx:244`），其列配置多出「左侧分组 tab + 搜索字段」，属外部应用增强，本规范不要求。

有列配置的表格页，弹窗形态一律照此，**禁止各页自造简版 checkbox 弹窗**：

1. **弹窗**：宽 `680px`，`display:flex; flexDirection:column`，三段式——标题栏 / 双栏主体 / 底部按钮。
2. **左栏**：全部列的勾选清单；取消勾选时**同步从固定列中移除**该列。
3. **右栏（`230px`）**：顶部两行元信息 `已选 N 列 · 拖动调顺序` + `📌最多固定{MAX}项（表格左侧冻结）`；每项四个操作——
   `⠿` 拖拽排序 · `⬆` 置顶 · `📌` 固定（左侧冻结）· `×` 删除。
4. **固定列上限 `MAX_PINNED_COLUMNS = 7`**，超出时不生效并给出提示。
5. **固定列渲染**：列顺序「固定列归组在前」，再按列宽**累加 `left` 偏移**，**逐格内联 sticky**——
   ⚠️ **固定列实际渲染宽度必须与偏移所用配置宽一致**：固定列单元格 `width/minWidth/maxWidth` 三值同设为配置宽+超宽省略号（td实际宽度由浏览器分配，不锁死则各固定列互相叠压——2026-08-18 订单利润V2实测踩过）。
   不得用 nth-child CSS（历史教训 `TASK_CHANGE_LOG:1280`：会导致表头/表体错位）；表头 zIndex 高于表体，**总计行的固定列同步吸左**。

## 12. 数值 0 与空值必须可区分（2026-08-16 需求方拍板，新规）

> 起因：2026-08-16 审计发现 `AiFinanceItemCashProfitV2.tsx` 有 **14 个数值列**写成 `value || "—"`，
> JS falsy 判断把**真实的 0** 渲染成「—」；与该页自身「本列应为 0」的 ⓘ 口径说明、以及总计行照常显示的 `¥0.00` **自相矛盾**，
> 直接后果是「销量 0」与「无销量数据」在页面上无法区分，掩盖了一个真实的数据问题。

- **数值列的真实 0 必须显示 `0` / `¥0.00`**，不得显示占位符。
- **只有 `null` / `undefined`（字段缺失、接口没返回）才显示占位符**。
- **禁止 `value || "—"` 这类 JS falsy 写法**；一律写成 `x == null ? 占位符 : 渲染(x)`。
- 字符串列（备注/描述/MSKU 等）用 `|| "—"` 不受此限——空字符串在语义上即为无值。
- 新增/改造表格页时**必须逐列扫一遍数值列**，不能只改被投诉的那一列。
- 占位符字符（半角 `-` 还是全角 `—`）全站尚未统一，见 §14 待定项③。

## 13. 行列高亮 = 点单元格淡色十字高亮（2026-08-16 拍板：禁止自造语义底色）
