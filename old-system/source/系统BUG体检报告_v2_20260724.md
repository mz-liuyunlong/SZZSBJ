## P0 — 立即处理：数据外泄链（多项叠加，实测可利用）

**0-1 Admin 后台 fail-open 裸奔（v1 已标，仍在）**
- 位置：`src/adminServer.ts:124` `if (!ADMIN_PASSWORD) { next(); return; }`
- 证据：数据侧实扫 `has_ADMIN_PASSWORD=false`（服务从 /opt/lingxing-auto/.env 读环境，无非空 ADMIN_PASSWORD）。
- 影响：除 internal-readonly 与卡片回调外，`/api/chat /api/hr/* /api/pmc/* /api/help/* /api/clearance-center/* /api/ai-business/* /api/lingxing-sales/*` 全部路由无任何凭证放行。
- 修复方向：未配置密码时 fail-closed（启动即拒绝或全路由 401）；至少启动打印醒目告警。

**0-2 端口 3001 对公网直连**
- 证据：`ss -lntp` → `0.0.0.0:3001`；外网 `curl -I http://42.193.254.170:3001/` → `HTTP/1.1 200 OK`。安全组未收敛到中转机IP。
- 影响：叠加 0-1，任何人可直接访问全部后台数据与功能。
- 备注：需求方 2026-07-24 表示 3001 网络收敛先不处理；但 0-1/0-3/0-4/0-5 是与 3001 独立的应用层项，成本低，建议优先。

**0-3 下载密码强度极弱 + 限流可绕过**
- 位置：`src/helpRoutes.ts:112`（限流键用可伪造的 `x-forwarded-for`）+ `dim_access_password` 数据。
- 证据：有效下载密码 `n=2, min_len=2`（2位密码）；每请求换假 XFF 即可无限次在线爆破。
- 影响：命中后拿到导出 token，可导出最多 50000 行业务数据。
- 修复方向：限流键改 socket.remoteAddress/可信代理链；下载密码强制≥12位并轮换；补账号级退避。

**0-4 导出 token 非真一次性**
- 位置：`src/helpRoutes.ts:43-50`（`isValidExportToken` 校验通过 `return true` 但从不删除 token）。
- 影响：注释声称"一次性"，实际 10 分钟内可无限复用；token 泄露即可反复批量导出。
- 修复方向：校验通过即从 exportTokens 删除；或改会话语义并限单token总行数。

**0-5 盘上残留明文密钥文件（v1 P0-2，仍在）**
- 证据：生产目录仍有 `./.envvvvvvfdfd`（v1 报告核实其含真实领星 APP_ID/SECRET）。部署目录无 .git，本批无法证明是否仍被 git 跟踪/是否已轮换。
- 修复方向：删除该文件；到领星后台轮换密钥（最稳）；核查是否曾推送过任何远端。

## P1 — 尽快处理：数据完整性与目标/规划口径

**1-1 dim_product.msku 无空值保护，静默算错毛利（latent，当前未触发）**
- 位置：`src/syncLingxingDailyToDb.ts:311` `msku = VALUES(msku)`（同段 sku/item_name 有 `IF(VALUES()='',保留,新值)` 保护，独漏 msku）；`:477` 广告FACT同款。
- 复现：领星某次未返回该item的msku → dim_product.msku被覆盖为空 → 下游成本表JOIN失配 → 毛利静默高估，不报错。
- 现状：数据侧 `empty_msku=0`，近14天无"写空"直接证据 → 判定为潜伏缺陷（护栏缺失但尚未触发）。
- 修复方向：比照sku/item_name加 `IF(VALUES(msku)IS NULL OR VALUES(msku)='',msku,VALUES(msku))`。

**1-2 update-lifecycle 多写操作缺事务**
- 位置：`src/feishuRawSalesRoutes.ts:1253` 路由内 INSERT event_clearance_approval + UPDATE 撤销 + UPDATE dim_product 无事务包裹；对照 update-owner(:1133) / update-wfs-fee(:1428) 均有事务。
- 复现：改生命周期时"撤销待审批"已提交但 dim_product 更新失败 → 审批态与业务态不一致且不可回滚。
- 修复方向：整函数 beginTransaction/commit/rollback。

**1-3 RAW层 DELETE-then-INSERT 无事务且空结果仍删（v1 P1-3，仍在）**
- 位置：`src/syncOrderProfitDaily.ts:454 DELETE → :463 空判断 → :485 INSERT`（无事务）；`src/syncLingxingToRawFeishu.ts:411-492` 同模式（<REDACTED_FEISHU_SHEET_ID>/<REDACTED_FEISHU_SHEET_ID>）。
- 复现：FACT未就绪时源查询返回空 → DELETE已提交 → return 0 → 当天RAW被清空不回填；或分批INSERT中途失败留"半天数据"。
- 修复方向：先判有数据再删；或DELETE+INSERT整体事务，失败回滚。

**1-4 目标写入未做负责人别名归一 → 同人拆两行、公司合计重复计数**
- 位置：`src/aiBusinessRoutes.ts:437`（写库用原始 `it.owner`）vs `:418` 锁定检查用 `normalizeOwner` vs `:585` confirm用归一。
- 复现：已有 `owner='林翔'` 目标行，用别名"啊四"再写 → 查不到旧行→INSERT新行→ `/progress`(:679) 归一聚合时两行都算林翔→目标翻倍、完成率失真。
- 修复方向：写入前统一 normalizeOwner；历史脏数据一次性归并。

**1-5 月度规划/目标 msku 聚合串作 JOIN key 不稳定 → 已填规划"失联"、重复建行**
- 位置：`src/aiBusinessRoutes.ts:913`（`p.msku=COALESCE(i.msku,d.mskus,'')` 用现算聚合串匹配）；唯一键含msku。
- 复现：item当月增减变体→GROUP_CONCAT串变→旧规划行匹配不上显示"未填"→重填→唯一键msku不同→新插一行→同品两条规划、对账对不上。
- 佐证：数据侧确认存在 `multi_msku_items=1`（真实样本，非纯理论）。
- 修复方向：业务匹配/唯一键改基于稳定的 `(plan_month,store_id,item_id)`，msku仅作展示字段。（注：清货中心月目标接口 batch3c 已用"先查(月+店+item)命中沿用其msku"规避，月度规划本体未规避。）

**1-6 CS测品排除口径不一致 → 幻影目标 + 误进规划清单**
- 位置：`src/aiBusinessRoutes.ts` `fetchCsSet`(:122) 有"msku LIKE 'CS%'"兜底，但 `computeNewProductTargets`(:239) 与 `/monthly-plan/todo`(:880,914) 只用 business_state 单条件。
- 复现：新CS测品状态表快照未及时标记 → 被当正常新品分配目标、被要求填月度规划（违反"CS不参与规划"）。
- 修复方向：把 fetchCsSet 的 union 兜底抽公共函数，替换两处单条件。

**1-7 月报库存数量漏"可用库存"(avail) → 非WFS库存品被低估/误判无库存**
- 位置：`月报系统/交付件/generate_monthly_report.py:284,557`（`total_qty=wfs+inbound`，SQL已查avail但未用）；weekly口径为WFS+可用+在途。
- 复现：仅常规仓有货(WFS=0)的品在月报库存件/库存金额/"有库存"卡片被算0。
- 修复方向：确认月报"库存数量"是否应含avail；若含则 `wfs+avail+inbound`。（**口径待需求方确认**再定P级）

**1-8 unmatchedOwnerNotify 网络异常时重复发生产群**
- 位置：`src/unmatchedOwnerNotify.ts:195-212`（单次axios.post，任何异常即降级再发一条文本到同一生产webhook，未用feishuNotify的重试/去重）。
- 复现：卡片实际已投递但响应超时/ECONNRESET → catch → 再发文本 → 群内"卡片版+文本版"重复轰炸。
- 修复方向：改走 feishuNotify.sendWithRetry/classifyError，仅确认失败才降级。

**1-9 backfillDailyChain 滑窗最老一天失败即掉出窗口，永久静默缺数据**
- 位置：`src/backfillDailyChain.ts:178-181`（窗口[T-6,T-2]）+ dirtyDates 逻辑；次日窗口平移，T-6 不再被任何一天覆盖。
- 复现：某日 rawSales(删日重写)对窗口最老一天失败 → 次日窗口已不含该日 → 该日RAW永久缺数据，除非人工按 SUMMARY_JSON.dirtyDates 重跑。
- 修复方向：dirtyDates 自动并入下次运行日期集合；或对 dirtyDates 强制告警+catch-all重跑。
