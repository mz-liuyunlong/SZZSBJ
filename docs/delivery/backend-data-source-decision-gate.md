# 后端接口数据源决策门禁

## 1. 目的

本门禁用于在后端业务接口 PRP 和实现之前，确认每个数据集的权威来源、短期方案、长期归属、字段血缘、退出条件和风险，防止接口在来源不明时直接读取旧库、实时批量拉取外部平台、默认双写或形成多个权威来源。

## 2. 适用范围

### 必须建立或更新数据源决策的情况

- 新增后端业务接口。
- 修改数据源。
- 修改字段来源。
- 修改公式。
- 修改聚合逻辑。
- 修改数据新鲜度。
- 修改权威归属。
- 修改旧库、外部 API、新库之间的取数责任。
- 修改会影响页面展示含义的数据契约。

### 可以复用已有决策的情况

以下情况可以复用已有数据源决策，但必须确认决策仍有效：

- 纯测试修复。
- 错误处理修复。
- 日志文案修复。
- 不改变数据契约的重构。
- 不改变字段来源的性能优化。
- 不改变业务含义的类型整理。
- 不改变接口语义的代码清理。

门禁不得退化为机械流程，也不得复制旧结论应付检查。只要数据来源、字段含义、公式、聚合、新鲜度或权威归属发生变化，就必须重新调查并确认。

纯文档、纯前端且不改变后端数据契约的任务不适用。

## 3. 强制执行顺序

```text
只读证据调查
  → 接口数据源决策
  → 必要的负责人确认
  → 编写并批准接口 PRP
  → 工程师实现
```

未完成数据源决策不得编写业务接口代码。任何数据集仍为 `NEED_OWNER_DECISION` 时，接口总体状态必须为 `BLOCKED_BY_OWNER_DECISION`，接口 PRP 不得进入实现。

### 3.1 旧系统与来源调查

在形成数据源分类和总体状态前，必须逐项填写下表，不得只写泛化的“关联证据”：

| 前置调查项 | 证据位置与调查结论 |
|---|---|
| 旧页面 |  |
| 旧 API |  |
| 旧接口文件位置 |  |
| 读取表 |  |
| 表写入方 |  |
| cron / 脚本 / 外部 API |  |
| 人工写库入口 |  |
| 外部平台重新获取可能性 |  |
| 少量配置数据可行性 |  |
| 短期策略 |  |
| 长期策略 |  |

这些字段是接口数据源决策的强制前置调查项，未完成不得进入接口 PRP。某项不适用时必须写明“不适用”及理由；无法由现有只读证据确认时，必须填写 `NEED_OWNER_DECISION` 或“待确认”，不得猜测。

### 3.2 决策文件位置与命名

接口级数据源决策文件默认存放在：

```text
docs/data-sources/decisions/{module}-{interface}-decision.md
```

- `{module}` 使用业务模块名。
- `{interface}` 使用接口或能力名。
- 文件名必须使用小写 kebab-case。
- 文件内的“接口总体状态”字段是该决策是否可以进入 PRP 的最终状态来源。
- `docs/integrations/**` 中的离线 API 文档只能作为调查证据，不是已批准的数据源决策。
- 决策文件存在不等于自动批准实现，仍须完成负责人确认、PRP 编写和 PRP 批准。

## 4. 数据源分类

| 分类 | 定义 | 必要约束 |
|---|---|---|
| `READ_LEGACY_TEMPORARILY` | 短期使用只读账号、明确表和受限查询读取旧 MySQL。 | 必须写明查询范围、性能边界、退出条件、替换计划和目标日期或可验证里程碑。 |
| `REBUILD_SYNC` | 外部平台是权威来源，新系统重新建设 integration、Celery 同步、标准化存储和质量检查。 | 禁止在 API route 中实时批量拉取外部平台；接口读取已同步的新系统数据。 |
| `MIGRATE_ONCE` | 有限的人工维护或历史主数据一次性迁入新 PostgreSQL，核对后切换所有权。 | 必须有数量核对、字段映射、切换点、回滚方案和迁移后写入归属。 |
| `NEW_SYSTEM_OWNED` | 新系统产生并维护的数据或配置，不依赖旧库作为持续权威来源。 | 必须说明写入入口、审计、版本或回滚要求。 |
| `ARCHIVE_ONLY` | RAW、backup、临时、废弃或仅供审计观察的数据。 | 不进入第一期业务接口，不得作为默认在线查询来源。 |
| `NEED_OWNER_DECISION` | 证据不足、口径冲突或所有权未确认时使用的临时阻塞状态。 | 不是最终策略；负责人决定前禁止实现。 |

聚合接口不得使用模糊的 `MIXED` 分类。不同来源必须拆到数据集或字段组逐项分类，并明确聚合规则和唯一权威来源。禁止默认双写。

## 5. 接口总体状态

接口总体状态只能是：

| 状态 | 含义 |
|---|---|
| `READY_FOR_PRP` | 所有数据集已有可执行分类、风险和审批要求已解决，可以编写接口 PRP。 |
| `BLOCKED_BY_OWNER_DECISION` | 至少一个数据集为 `NEED_OWNER_DECISION`，或必须确认的事项尚未获负责人决定。 |

数据源决策完成不等于批准实现；`READY_FOR_PRP` 只允许进入 PRP 编写和审批。

## 7. 数据集分类表

| 数据集或字段组 | 业务用途 | 当前权威来源 | 分类 | 短期策略 | 长期策略 | 退出条件或切换点 | 需负责人确认 |
|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  | 是 / 否 |

每一行只能选择一种分类。聚合接口必须拆分数据集或字段组，不得填写 `MIXED`。

财务、利润、成本、费用、结算、退款、汇率、库存和广告指标必须明确公式、时间口径、币种与新鲜度。

## 9. 风险检查清单

- [ ] 每个数据集或字段组已有且仅有一种分类。
- [ ] 不存在未解决的 `NEED_OWNER_DECISION`。
- [ ] 权威来源、写入方、字段定义、公式、时区、币种和新鲜度均有证据。
- [ ] `READ_LEGACY_TEMPORARILY` 已限定只读账号、表、查询范围和性能边界，并有退出条件。
- [ ] `REBUILD_SYNC` 使用 integration、Celery、标准化存储和质量检查，不在 API route 实时批量拉外部平台。
- [ ] `MIGRATE_ONCE` 已定义数量核对、字段映射、切换点和回滚方案。
- [ ] 不读取 `ARCHIVE_ONLY` 数据提供第一期在线接口。
- [ ] 不默认双写，不存在未定义优先级的多个权威来源。
- [ ] 敏感字段已标记，后续 PRP 将说明权限、脱敏和审计要求。
- [ ] 调查未连接真实数据库、调用真实外部 API 或修改任何数据；如确需验证，已另获明确授权。

## 12. 必须由负责人确认的场景

- 财务、利润、成本、费用、结算、退款、汇率口径。
- 库存可用量、在途量、安全库存。
- 广告花费、归因、ACOS、ROAS。
- 使用 `READ_LEGACY_TEMPORARILY`。
- 使用真实外部 API 或 `REBUILD_SYNC`。
- 任何 `MIGRATE_ONCE`。
- 数据切换、回填或历史重算。
- 人工写库、双写或多个权威来源。
- 来源表写入方、公式、时区、币种或新鲜度无法确认。
- 读取 RAW、backup、临时表或大表。
- 员工、客户、店铺等敏感数据。
- 连接真实数据库或验证真实外部 API。
- 重新启用 `deleted_interfaces` 或 `do-not-use` 中的接口。
- 短期方案与长期方案冲突。
- 旧库只读方案没有明确退出条件。

负责人的数据源决定不替代连接真实数据库、调用真实外部 API、迁移、写库或部署所需的单独明确授权。

## 13. 工程师可自行完成的只读调查范围

在不触碰 `old-system/`、真实数据库、真实外部 API、密钥和生产环境的前提下，工程师可以：

- 阅读当前任务明确允许的项目文档、已批准 PRP、schema、模型、迁移和测试。
- 检查新系统代码中的 route、service、repository、同步任务和字段使用关系。
- 检查已纳入仓库且允许读取的 OpenAPI、数据字典、示例响应和历史决策记录。
- 使用仓库搜索整理调用方、字段映射、写入方和已知风险。
- 将无法由现有证据确认的问题标记为 `NEED_OWNER_DECISION`。

读取 `old-system/`、连接真实数据库或验证真实外部 API 不属于默认只读调查权限，必须遵守任务授权和项目最高规则。

## 14. 禁止事项

- 未完成数据源决策或总体状态不是 `READY_FOR_PRP` 时编写业务接口代码。
- `NEED_OWNER_DECISION` 未解决时以假设替代负责人决定。
- 用 `MIXED` 掩盖聚合接口的数据集差异。
- 在 API route 中实时批量拉取外部平台。
- 默认双写，或在未定义优先级时并存多个权威来源。
- 将 RAW、backup、临时或废弃数据默认用于第一期在线接口。
- 在未获明确授权时读取或修改旧系统、连接真实数据库、调用真实外部 API、写库、迁移、同步或部署。
- 在决策文档、PRP、代码、日志或测试中写入真实密钥。

## 15. 验收标准

- [ ] 已按强制顺序完成只读证据调查和接口数据源决策。
- [ ] 所有数据集或字段组均已单独分类，不使用 `MIXED`。
- [ ] 总体状态仅为 `READY_FOR_PRP` 或 `BLOCKED_BY_OWNER_DECISION`。
- [ ] 所有 `NEED_OWNER_DECISION` 均保持阻塞，或已有负责人批准记录。
- [ ] 数据血缘、短期策略、长期策略、退出条件、切换点和风险完整。
- [ ] 涉及旧库、同步、迁移、敏感数据或关键业务口径时已取得必要确认。
- [ ] 接口 PRP 引用本决策文件、总体状态和负责人结论。
- [ ] 未在门禁阶段编写业务接口、修改数据库或调用真实外部系统。
