# WFS 待发货打包单开发需求

## 规范与实施门禁

本文件为 2026-10-29 的开发需求评审稿，依据 WFS 业务产品需求文档 V2.0 及同版流程图。业务要求与旧代码冲突时，以 V2.0 为准。本文不是已批准 PRP，也不授权调用真实外部 API、连接生产数据库或部署。

固定技术栈：Python 3.13、FastAPI、Pydantic、SQLAlchemy 2、PostgreSQL、Alembic、Redis/Celery；前端 React/TypeScript、Ant Design/ProComponents、React Router、Zustand。复用现有基础设施，不新增独立管理后台或第二套任务系统。

实施前顺序：接口数据源调查与负责人决定 → READY_FOR_PRP → 对应 PRP 审批 → 授权实施。存在 NEED_OWNER_DECISION 时，受影响接口不得编码。本文件中的接口、字段和权限扩展均为候选契约，不能当作已存在接口。

外部数据经来源登记、RAW 留证、标准化、业务事实、必要的读模型提供查询；前端业务 API 不直接读 RAW，不运行时依赖旧服务或旧库。人工记录与同步事实分开。新表或迁移需另行批准，禁止改公共 CI、启动脚本、全局忽略规则、其他任务记录或公共调度。

统一返回 { success, data, error, meta, request_id }，必须有请求/响应 schema、response_model、错误码、OpenAPI 和 Markdown API 文档；meta 提供来源、数据时间和过期状态。外部 ID、GTIN 用字符串保留前导零；时间 UTC 存储、Asia/Taipei 展示，Walmart 业务日 America/Los_Angeles；日期精度不足不得伪造时间。金额使用 numeric(18,4) 并带币种，未取得值为 null，不以零代替。

页面复用 MainLayout、PageShell、现有 WFS Frame、表格/筛选/详情组件；在实施 PRP 中确认实际组件路径。四 Tab 保持一致，帮助入口新标签打开本页 SOP。接口后端校验 permissionKey、账号与店铺数据范围，统计、详情、任务和附件同样受控。测试单与正式数据明确隔离。

完成标准：业务/API/页面实现、权限与数据范围验证、适用 pytest/Vitest/TypeScript/ESLint/构建及 Playwright、API 文档、SOP、接口 registry、交接与回滚说明均完成。测试使用隔离测试数据库、模拟外部服务和脱敏样例，不使用生产凭证。不得把静态页面或 mock 当完成。

## 1 目标与范围

让用户选择本次发货箱数、填写拆分货件数量并分配各货件箱数，确认发货信息后直接创建 WFS 货件并获取箱唛。无创建审批；不设置批准、驳回或待审批状态。国内仓上游原有审批不因此被取消。

分仓探测为可选辅助按钮，不能成为必须经过的步骤；未探测或探测失败不自动禁止合法创建。取消本次创建指请求提交前终止，不等于取消已存在的外部货件。

## 3 页面功能与字段

筛选：店铺、PK/OWS/商品关键词、打包完成日期、可安排/部分安排/已安排、创建结果及测试标识。列表按 PK 展示；展开装箱供核对，不要求用户勾选装箱行作为主要入口。

| 字段组 | 必需内容 |
|---|---|
| 单据 | 内部稳定 ID、PK、关联 OWS、店铺、商品标识、完成时间、单据版本 |
| 数量 | 总箱数/件数、已占用箱数、已成功安排箱数、剩余可发箱数 |
| 装箱核对 | 箱规、每箱件数、尾箱、箱号或稳定范围、装箱版本 |
| 处理状态 | 阻塞原因、可创建标记、关联创建记录、任务与箱唛状态 |

统计卡和列表共用权限/筛选口径；明确“可安排 PK 数”与“箱数”不同。创建失败和全部占用但结果未明的记录仍能从待处理入口找到。

创建抽屉：发货箱数 → 拆分分配 → 填写信息 → 确认创建 → 结果。探测为旁路按钮，不占必填步骤。显示申请拆分数量与实际外部货件数量，不假设两者相等。

## 4 分箱规则

1. 本次箱数为正整数且不超过可用量；拆分数量为正整数，不大于本次箱数；每票至少一箱；各票箱数之和等于本次箱数。
2. 装箱合计与 PK 一致，未完成、作废、身份不明、版本过期或数量不一致时阻止提交。
3. UI 按箱数操作，服务端必须映射到稳定实物箱/范围。相同箱规可按确定顺序分配；混合箱规和尾箱应生成可核对分配方案，不能平均换算件数。
4. 比如 30 箱，本次 20 箱拆 12+8，剩余 10 箱。若含尾箱，应明确尾箱归哪票及真实件数。
5. 预览分配不永久占用；最终确认时在一个事务中复核版本、占用和记录。并发请求不能安排同一箱两次。
6. 多票本地提交建议全部成功或全部失败；外部调用无法原子完成，必须逐票记录成功、失败、未知和已占用箱子。
7. 未确定混箱排序、跨 PK 合并和单票商品限制前，不默认拆分生产箱子，不静默减少所选数量。

## 5 创建与恢复

状态分开记录：创建 QUEUED/RUNNING/SUCCEEDED/FAILED/UNKNOWN/PARTIAL；箱唛 PENDING/READY/FAILED；领星同步 PENDING/SYNCED/STALE。不得新增创建审批域。

用户确认内容形成不可变操作快照，保存店铺、商品、箱数、件数、地址、类型、来源版本和请求关联。幂等键相同且内容相同返回原结果，同键不同内容报冲突。worker 原子领取；任务与业务记录可靠投递，采用项目已有能力。

超时可能已写入：UNKNOWN 保持占用，先回读核实；确定未创建后才能重试。外部成功但内部记录失败要通过关联回读恢复。箱唛失败只补取箱唛，不重新创建。进程重启和浏览器关闭不丢任务。

提交前取消不发创建请求；执行中不能伪装成提交前取消。真实外部取消、数量修改及已发货资源释放需独立需求和高危权限，不在此处顺手开发。

## 6 数据与接口能力

| 数据组 | 候选来源分类 | 要求 |
|---|---|---|
| PK/装箱/商品与店铺身份 | NEW_SYSTEM_OWNED | 使用现有国内仓与商品映射契约，核实 OWS 是否仍为必填 |
| 分配/创建操作/执行记录 | NEW_SYSTEM_OWNED | 稳定身份、版本、审计、可恢复 |
| 探测/创建/箱唛结果 | 外部受控操作及留证 | Walmart 当前官方契约待核实；历史票据不是当前可执行授权 |
| 旧草稿与模拟批次 | ARCHIVE_ONLY 或待决定迁移 | 禁止自动当真实货件导入 |

现有基路径 /api/pmc/wfs/pending-packing 可复用，禁止另起平行接口。候选能力：GET orders/summary/detail；POST allocation-preview；POST creation-operations；GET creation-operations/{id}；POST optional-previews；GET optional-previews/{id}；受控补取标签/核实结果。最终路径在 PRP 确定。

提交输入最少含 order_id、expected_version、expected_box_version、shipping_boxes、shipment_count、各票箱数及可核对箱范围、店铺、商品、地址、类型、幂等键。探测 ID 可空且不得必填。输出 operation_id、各票状态、实际计划/货件和标签状态；异步受理不返回假成功。

错误场景：信息不全、超可用量、分配不守恒、版本冲突、重复占用、越权、外部校验失败、结果未知。具体错误码需登记，不泄露平台密钥。

现有 page:pmc:wfs:view 可作为页面权限基准；draft-submit 不自动获得真实外部写权限。新增创建/探测/核实/补标签动作权限须单独登记。按 V2.0，确认创建替代本环节审批，但仍有后端授权、确认摘要、审计和异常恢复；本需求不授权真实写入执行。

## 7 验收与切片

| 场景 | 预期 |
|---|---|
| 30 箱发 20，拆 12+8 | 分配守恒，余 10 箱 |
| 多箱规、尾箱 | 各票件数来自实际箱子，不平均推算 |
| 两人同时安排同箱 | 仅一个成功，另一明确冲突 |
| 不探测直接确认 | 能正常受理，不出现审批 |
| 提交前取消 | 无 Walmart 创建调用 |
| 超时但外部已创建 | 核实恢复，不重复创建 |
| 多票部分成功 | 成功货件可见，失败票独立处理 |
| 箱唛失败 | 仅补取，已创建货件保留 |
| 越权访问任务或标签 | 后端拒绝 |
| 关闭页面后重开 | 恢复持久状态 |

切片：箱数分配契约与后端 → 待发货交互 → 可选探测 → 受控创建/恢复 → 标签与结果联调。每项单独 PRP 和测试，外部写能力独立授权。回滚关闭新写入，继续回读核实，不能删除占用和操作证据。

待确认：分箱排序与混箱策略、跨 PK 合并、平台拆分限制、真实创建契约及地址语义、旧 pending 草稿处理。以上未解决时对应能力保持阻塞。
