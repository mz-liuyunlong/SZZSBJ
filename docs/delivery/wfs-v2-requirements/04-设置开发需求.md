# WFS 设置开发需求

## 规范与实施门禁

本文件为 2026-10-29 的开发需求评审稿，依据 WFS 业务产品需求文档 V2.0 及同版流程图。业务要求与旧代码冲突时，以 V2.0 为准。本文不是已批准 PRP，也不授权调用真实外部 API、连接生产数据库或部署。

固定技术栈：Python 3.13、FastAPI、Pydantic、SQLAlchemy 2、PostgreSQL、Alembic、Redis/Celery；前端 React/TypeScript、Ant Design/ProComponents、React Router、Zustand。复用现有基础设施，不新增独立管理后台或第二套任务系统。

实施前顺序：接口数据源调查与负责人决定 → READY_FOR_PRP → 对应 PRP 审批 → 授权实施。存在 NEED_OWNER_DECISION 时，受影响接口不得编码。本文件中的接口、字段和权限扩展均为候选契约，不能当作已存在接口。

外部数据经来源登记、RAW 留证、标准化、业务事实、必要的读模型提供查询；前端业务 API 不直接读 RAW，不运行时依赖旧服务或旧库。人工记录与同步事实分开。新表或迁移需另行批准，禁止改公共 CI、启动脚本、全局忽略规则、其他任务记录或公共调度。

统一返回 { success, data, error, meta, request_id }，必须有请求/响应 schema、response_model、错误码、OpenAPI 和 Markdown API 文档；meta 提供来源、数据时间和过期状态。外部 ID、GTIN 用字符串保留前导零；时间 UTC 存储、Asia/Taipei 展示，Walmart 业务日 America/Los_Angeles；日期精度不足不得伪造时间。金额使用 numeric(18,4) 并带币种，未取得值为 null，不以零代替。

页面复用 MainLayout、PageShell、现有 WFS Frame、表格/筛选/详情组件；在实施 PRP 中确认实际组件路径。四 Tab 保持一致，帮助入口新标签打开本页 SOP。接口后端校验 permissionKey、账号与店铺数据范围，统计、详情、任务和附件同样受控。测试单与正式数据明确隔离。

完成标准：业务/API/页面实现、权限与数据范围验证、适用 pytest/Vitest/TypeScript/ESLint/构建及 Playwright、API 文档、SOP、接口 registry、交接与回滚说明均完成。测试使用隔离测试数据库、模拟外部服务和脱敏样例，不使用生产凭证。不得把静态页面或 mock 当完成。

## 1 目标

在 WFS 页面第四个 Tab 维护时效、提醒、异常判断、创建默认值和按需探测偏好；配置持久化、版本化、有生效范围和审计。不存在使探测成为必经步骤或重新开启创建审批的设置。

## 2 旧代码与现状差距

旧 app-d.jsx 的 TabSettings 包含节点×地区×物流商×渠道规则、店铺联系人/地址、仓库地区映射、物流字典和默认值，但大量内容在 useState，刷新可能丢失，不能当正式配置系统。

发现 ruleRows 初始化把业务 key 改成数字，而 setDays 使用该 key 更新规则对象；需以稳定 rule_code 建模，禁止用表格行号代表业务规则。规则中的天数与短少“件数”不能统一用“天”编辑。

旧 ITS 开关部分为示例，不能在本地打开即可取得平台权限。历史 returnAddress 不自动等同当前 shipFrom。旧运输日期、预计到仓和每托箱数等默认值须逐项核实，不直接迁入生产。

新 WfsSupportPages.tsx 标记为 frontend only/local settings。已有界面是设计参考，不代表持久配置、发布和规则执行已实现。

## 3 配置分组和字段

| 分组 | 核心字段 | 约束 |
|---|---|---|
| 时效 | rule_code、节点、地区、物流商/渠道、店铺范围、天数、起算节点 | 仅对证据明确的节点计算 |
| 提醒 | 提前时间、重复间隔、接收范围、集成引用 | 引用已有渠道，不存 Webhook |
| 异常 | 类型、开关、数量容差、单位、严重度、适用范围 | 天/件/次数使用不同单位校验 |
| 默认值 | 店铺、常用地址及用途、普通/ITS 等 | 只影响新表单，不能改已确认记录 |
| 可选探测偏好 | 候选地址、仓库/地区偏好 | 不强制探测，不承诺仓库分配 |
| 字典支撑 | 物流商、渠道、FC/地区关联 | 外部字典只读；人工地区映射单独版本留痕 |

字段是否首版需要以产品范围为准，不能因为旧页有联系人/托盘字段就扩大范围。涉及费用的配置应另走费用版本治理，不在此页硬编码收费规则。

## 4 生效和冲突规则

配置草案编辑 → 校验 → 影响预览 → 授权发布/按要求审批 → 到期生效 → 后台刷新计算。货件创建不审批与配置发布治理是不同事项，不恢复创建审批。

每版保存 rule_version、effective_from/to、change_reason、操作者、批准人/批准时间（适用时）、审计。历史不可覆盖，回退发布旧内容的新版本。涉及费用及其他项目要求审批的规则必须满足审批要求；普通配置是否需审批由负责人确定。

同一范围、同一生效区间多个规则必须有确定匹配策略。候选为显式 priority，同级冲突拒绝发布；不能静默最后保存覆盖。无匹配规则显示未配置，不能悄悄回落演示阈值。

阈值合法范围、单位、适用节点、日期区间、禁用引用、提醒对象授权由后端校验。零值表示禁用还是即时触发必须在每类规则明确定义，不默认等价。

## 5 影响预览与后台处理

预览固定 data_asof 和候选版本，显示受影响货件数、新增/恢复异常数及无法判断项，不修改案件、不发送通知。只展示用户有权范围；发布影响超出权限时需有全局发布权限。

发布与重算分别显示状态。重算失败保留上一版成功读模型并提示，不能让卡片和列表混用版本；可重新执行同版本任务。历史案件保留当时输入和命中规则，不能覆盖为新结论。

创建默认值更新只作用新草稿；已确认创建内容保持不变。探测结果输入变化时标过期，未探测仍可创建。业务用户无法通过本页开启真实平台能力、修改凭证或扩大店铺访问权。

## 6 页面与接口契约

页面按分组展示有效版本、生效范围、配置单位和最近变更；编辑抽屉提供当前/新值对照；预览显示后台进度；详情展示版本和审计。空配置、无权限、冲突、保存失败、发布待生效、重算失败应区分。

候选 API：
- GET settings：适用范围内有效版本及配置分组。
- GET settings/versions/{id}：内容、历史及审计。
- POST settings/versions：保存草案，含 expected_version、原因、范围和字段。
- POST settings/versions/{id}/preview：返回异步预览任务。
- POST settings/versions/{id}/publish：权限/审批条件满足后发布。
- 回退创建新版本，不修改旧版本记录。

错误包括范围无权限、非法单位/值、版本冲突、生效期冲突、引用无效、审批条件未满足、预览过期。发布接口不能由前端按钮隐藏替代后端权限。

权限按查看/编辑/预览/发布/回退分别登记，与现有 page:pmc:wfs:view 协调。敏感费用字段按字段权限过滤。配置集成引用不返回密钥；通知对象不能任意填入未授权外部地址。

## 7 数据与验收

规则/默认值/映射为 NEW_SYSTEM_OWNED；领星物流字典 REBUILD_SYNC；平台能力为已批准集成查询结果；旧示例阈值 ARCHIVE_ONLY。规则引擎和读模型必须引用同一规则版本，不各自维护阈值。

| 场景 | 预期 |
|---|---|
| 修改草案后刷新 | 内容持久化，有效规则未被直接覆盖 |
| 件数阈值编辑 | 显示件，不是天 |
| 同范围同级重叠规则 | 拒绝发布并指明冲突 |
| 无匹配规则 | 未配置，不使用演示默认值 |
| 预览 | 不发送通知、不改变案件 |
| 规则生效重算失败 | 提示失败，上一成功结果可查 |
| 发布新默认地址 | 已确认货件内容不变 |
| 配置探测偏好 | 不把探测变成必填 |
| 回退版本 | 新增版本，历史可追溯 |
| 无权限发布或读取跨店配置 | 后端拒绝 |
| ITS 本地配置 | 不伪造平台授权 |
| 重复发布/重算 | 幂等，无重复通知 |

切片：规则结构与决策 → 持久化/版本 API → 影响预览/生效任务 → 设置页面 → 异常模块联调。回滚停止发布或重新发布已知版本，不删除审计。

待确认：初始有效阈值、规则优先级、零值含义、生效时点与历史重算范围、哪些配置需要审批、通知策略及字典来源。不能从旧 Demo 推定这些事项已被批准。
