# WFS 异常中心开发需求

## 规范与实施门禁

本文件为 2026-10-29 的开发需求评审稿，依据 WFS 业务产品需求文档 V2.0 及同版流程图。业务要求与旧代码冲突时，以 V2.0 为准。本文不是已批准 PRP，也不授权调用真实外部 API、连接生产数据库或部署。

固定技术栈：Python 3.13、FastAPI、Pydantic、SQLAlchemy 2、PostgreSQL、Alembic、Redis/Celery；前端 React/TypeScript、Ant Design/ProComponents、React Router、Zustand。复用现有基础设施，不新增独立管理后台或第二套任务系统。

实施前顺序：接口数据源调查与负责人决定 → READY_FOR_PRP → 对应 PRP 审批 → 授权实施。存在 NEED_OWNER_DECISION 时，受影响接口不得编码。本文件中的接口、字段和权限扩展均为候选契约，不能当作已存在接口。

外部数据经来源登记、RAW 留证、标准化、业务事实、必要的读模型提供查询；前端业务 API 不直接读 RAW，不运行时依赖旧服务或旧库。人工记录与同步事实分开。新表或迁移需另行批准，禁止改公共 CI、启动脚本、全局忽略规则、其他任务记录或公共调度。

统一返回 { success, data, error, meta, request_id }，必须有请求/响应 schema、response_model、错误码、OpenAPI 和 Markdown API 文档；meta 提供来源、数据时间和过期状态。外部 ID、GTIN 用字符串保留前导零；时间 UTC 存储、Asia/Taipei 展示，Walmart 业务日 America/Los_Angeles；日期精度不足不得伪造时间。金额使用 numeric(18,4) 并带币种，未取得值为 null，不以零代替。

页面复用 MainLayout、PageShell、现有 WFS Frame、表格/筛选/详情组件；在实施 PRP 中确认实际组件路径。四 Tab 保持一致，帮助入口新标签打开本页 SOP。接口后端校验 permissionKey、账号与店铺数据范围，统计、详情、任务和附件同样受控。测试单与正式数据明确隔离。

完成标准：业务/API/页面实现、权限与数据范围验证、适用 pytest/Vitest/TypeScript/ESLint/构建及 Playwright、API 文档、SOP、接口 registry、交接与回滚说明均完成。测试使用隔离测试数据库、模拟外部服务和脱敏样例，不使用生产凭证。不得把静态页面或 mock 当完成。

## 1 目标与边界

依据可靠的领星履约数据和版本化规则发现业务异常，形成分配、核实、跟进、解决、关闭的持久处理记录。创建超时属于创建记录的技术处理，不将所有任务失败混进履约异常。

首版记录平台申诉编号、证据和期限，不自动向平台提交申诉。货件创建无需审批，不改变异常处置本身的权限边界。

## 2 代码证据

旧 app-a.jsx 的 buildExceptions、bigGaps、itemRows 提供阶段性异常思路：超预计到仓、已签收未入库、收货不完整、关闭短少。旧 app-d.jsx 的 groupExceptions、TabException 和 ExceptionDrawer 提供按货件聚合与处理界面。

不得直接沿用：
- EX-递增序号作为长期主键。
- exOv/useState 作为持久案件状态。
- 固定货件复议示例、预计到仓加两天作为真实签收日期。
- 固定 D+10/D+50/30 天当作现行平台政策。
- Walmart/众壹混合来源判定替代 V2.0 领星链。
- 将缺失数量默认零，或未经证据取两来源破损数最大值。

新 WfsSupportPages.tsx 明确为 frontend only，观察到空列表及本地状态；这不是异常后端已交付。warehouse_wfs 是既有费用异常领域，不能仅因名称相似复用其业务规则或改变其案件。

## 3 规则输入与输出

| 异常族 | 必需证据 | 缺失处理 |
|---|---|---|
| 创建长期未发货 | 创建时间、有效状态、可靠的未发货事实 | 同步缺失则待核实 |
| 到仓超期 | 有效预计日期、未实际到仓事实 | 日期/覆盖缺失不判异常 |
| 到仓后未开始收货 | 实际到仓、收货/入库完整覆盖 | 无实际日期不以预计替代 |
| 收货长期未完成 | 起算节点、可比发货量和收货量 | 口径不一致不计算短少 |
| 关闭短少/破损 | 关闭事实、商品级发货/接收/破损 | 不跨商品抵消 |
| 申诉临期 | 核实截止日及未结束案件 | 无截止日显示待核实 |

规则返回“命中/未命中/无法判断”，保留 rule_version、data_asof、输入证据及解释。阈值由设置提供，本文不批准生产默认天数。短少与破损是否重叠、容差按 SKU 还是 GTIN，需要指标决定后再实现。

## 4 持久化案件流程

检测事件与案件分开：事件记录规则命中事实；案件记录人工处理。逻辑实体包括事件、案件、处理事件、附件引用、通知发送记录，不等于批准建表。

去重身份建议使用店铺、货件、商品粒度、规则族及异常周期；规则版本用于证据，重算不能仅因版本变化新建重复案件。恢复后再次发生是否重开或新建由规则确认。

案件状态候选：待处理 → 处理中 → 待外部反馈 → 已解决 → 已关闭；允许授权重开。分配、备注、证据、平台编号、期限修改、解决和关闭都记录操作者、时间、原因。关闭需原因，历史不可覆盖。

指标恢复只标记事件恢复，不自动删除记录或关闭未完成申诉。通知按案件、提醒阶段、周期去重；重试发送不得重复通知。通知渠道复用统一集成，首版不默认发送到外部。

## 5 页面和接口

列表支持店铺、货件/商品、类型、严重程度、负责人、状态、发现日期和临期筛选。主列表可按货件聚合；Tab 徽标为未结束异常货件去重数，案件数和事件数另标。

详情包含事实对账、规则解释、来源更新时间、负责人、截止日期与依据、平台案件编号、附件、处理时间线。日期未知明确提示，不伪造倒计时。

候选能力：
- GET exceptions：分页列表与同口径统计。
- GET exceptions/{id}：案件、事件、证据与处理历史。
- POST exceptions/{id}/assign：负责人和版本。
- POST exceptions/{id}/events：备注/解决/关闭/重开，expected_version、原因。
- 受保护附件上传/下载：绑定案件、类型/大小校验、恶意文件检测沿用现有能力。
- 手动重算为受控后台任务，不在查询路由执行全量扫描。

所有 mutation 校验版本与状态，禁止覆盖他人同时修改；同动作幂等。错误含案件不存在/无权限、版本冲突、非法状态转移、证据不足、来源过期。不得在错误中暴露无权限对象。

复用页面权限；分配、处理、关闭、重开、附件、通知分别登记 permissionKey。负责人可选范围受组织及数据范围约束，不能通过分配扩大查看权限。

## 6 数据源与验收

履约事实读取看板批准的新系统事实/读模型，不能从页面或旧 HTML 抽取；规则版本来自设置；案件为 NEW_SYSTEM_OWNED；旧模拟异常 ARCHIVE_ONLY。历史真实案件迁移需单独决定。

| 场景 | 预期 |
|---|---|
| 同一数据反复检测 | 不重复建案件或发提醒 |
| 一货件多条异常 | 事件分别保留，货件徽标只计一次 |
| 同步过期或字段缺失 | 无法判断，不误报短少 |
| 超收与另一商品短少 | 不互相抵消 |
| 保存记录后刷新/换用户 | 持久记录存在，权限正确 |
| 并发关闭与修改 | 一个按版本成功，另一个冲突 |
| 截止日未知 | 不产生虚假临期提醒 |
| 已关闭后重开 | 原历史完整，重开原因可查 |
| 调整规则后重算 | 原证据保留，去重稳定 |
| 跨店查询或附件下载 | 后端权限阻断 |

切片：规则判定纯业务服务 → 事件/案件持久化 → 处理 API → 页面 → 批准后的通知接入。回滚关闭检测和新通知，保留案件查询与证据。

待确认：准确指标口径、异常周期和重开策略、关闭责任、申诉政策、保留期和通知接收范围。未确认政策不得写死。
