# WFS 货件看板开发需求

## 规范与实施门禁

本文件为 2026-10-29 的开发需求评审稿，依据 WFS 业务产品需求文档 V2.0 及同版流程图。业务要求与旧代码冲突时，以 V2.0 为准。本文不是已批准 PRP，也不授权调用真实外部 API、连接生产数据库或部署。

固定技术栈：Python 3.13、FastAPI、Pydantic、SQLAlchemy 2、PostgreSQL、Alembic、Redis/Celery；前端 React/TypeScript、Ant Design/ProComponents、React Router、Zustand。复用现有基础设施，不新增独立管理后台或第二套任务系统。

实施前顺序：接口数据源调查与负责人决定 → READY_FOR_PRP → 对应 PRP 审批 → 授权实施。存在 NEED_OWNER_DECISION 时，受影响接口不得编码。本文件中的接口、字段和权限扩展均为候选契约，不能当作已存在接口。

外部数据经来源登记、RAW 留证、标准化、业务事实、必要的读模型提供查询；前端业务 API 不直接读 RAW，不运行时依赖旧服务或旧库。人工记录与同步事实分开。新表或迁移需另行批准，禁止改公共 CI、启动脚本、全局忽略规则、其他任务记录或公共调度。

统一返回 { success, data, error, meta, request_id }，必须有请求/响应 schema、response_model、错误码、OpenAPI 和 Markdown API 文档；meta 提供来源、数据时间和过期状态。外部 ID、GTIN 用字符串保留前导零；时间 UTC 存储、Asia/Taipei 展示，Walmart 业务日 America/Los_Angeles；日期精度不足不得伪造时间。金额使用 numeric(18,4) 并带币种，未取得值为 null，不以零代替。

页面复用 MainLayout、PageShell、现有 WFS Frame、表格/筛选/详情组件；在实施 PRP 中确认实际组件路径。四 Tab 保持一致，帮助入口新标签打开本页 SOP。接口后端校验 permissionKey、账号与店铺数据范围，统计、详情、任务和附件同样受控。测试单与正式数据明确隔离。

完成标准：业务/API/页面实现、权限与数据范围验证、适用 pytest/Vitest/TypeScript/ESLint/构建及 Playwright、API 文档、SOP、接口 registry、交接与回滚说明均完成。测试使用隔离测试数据库、模拟外部服务和脱敏样例，不使用生产凭证。不得把静态页面或 mock 当完成。

## 1 目标与来源边界

展示实际货件、标签、创建与同步状态；从领星获取发货、运输、到仓和收货入库信息。本页不执行确认发货、确认到仓、确认收货，不新增物流作业系统。

本系统创建成功是看板可见的充分条件，不需要等待领星先同步。创建结果与标签来自受控创建能力；履约信息来自领星，不能擅自恢复旧 Demo 的 Walmart Receipt/众壹混合取数作为正式主链。

## 3 页面与字段契约

筛选：店铺、实际计划/货件号、PK、商品、日期、状态、目的仓、物流商、渠道、异常、测试标识。货件视图按实际 shipment 去重；商品视图按店铺、货件、商品身份聚合，不按 SKU 名称跨店合并。

| 字段组 | 最小内容 |
|---|---|
| 创建身份 | 内部记录、store_id、inbound_order_id、shipment_id、来源、关联 PK |
| 商品 | GTIN、MSKU、ItemID、标题、箱数与件数 |
| 履约 | 领星原始状态、规范状态、发货/运输/到仓/入库节点和来源 |
| 数量 | declared_units、shipped_units、received_units、入库量、破损和差异 |
| 时间 | source_updated_at、last_successful_sync_at、data_asof、stale |
| 操作结果 | label_status、同步状态、异常货件标记、案件链接 |

数值必须有语义和来源：实际发货不等于申报；收货不等于可售。领星无法提供独立入库量时，字段为 null 并标缺失，不借用旧 Walmart 数据暗中补齐。数量差异只有双方覆盖完整、单位一致时计算；不能跨商品抵消短少和超收。

未知外部枚举保留原值并标“待映射”；不能当 CLOSED。平台关闭、内部履约完成、异常结案分别展示。

## 4 后端读模型与同步

候选分类：创建记录 NEW_SYSTEM_OWNED；领星货件/SP/履约数据 REBUILD_SYNC（优先复用已批准接入）；看板 MART 为可重建投影。每组需要来源决策及字段血缘。

按 source_account_ref/store_id/shipment_id 建立核实后的关联，inbound_order_id 是计划而非货件；同一计划可能多张货件。跨来源去重保留映射证据，不能只凭 SKU 自动认领外部货件。

后台增量同步保留游标、重叠窗口、分页覆盖、批次和去重规则；失效或部分失败时保留最后成功数据并提示过期。用户刷新触发已有受控任务或读取状态，不让请求路由实时批量拉外部 API。禁止为此改公共调度。

仅外部来源货件纳入范围、历史保留、取消与测试统计按负责人决定。未关联 PK 的货件显示待关联，人工关联需要独立权限和审计，不能直接改外部事实。

## 5 API 与交互能力

候选 GET shipments、shipments/{id}、shipment-products、shipments/{id}/timeline、shipments/{id}/labels；复用现有 /api/pmc/wfs 命名空间并在 PRP 决定路径。

查询入参统一过滤、分页、排序，排序字段白名单；输出 rows、total、同口径 summary 及 data_asof。详情含来源及异步创建关联。标签通过授权下载，不暴露可猜测公共地址。

页面卡片点击转对应过滤。抽屉分创建信息、领星同步信息、数量对账、关联异常和追溯。节点实际/预计分开显示，不制造进度百分比；空数据、加载、失败、过期、无权限分别表达。

权限基准 page:pmc:wfs:view；标签下载、外部关联为独立动作。统计、分页、导向链接都限制账号与店铺。无权限时不得通过异常数量泄露其他店铺信息。

## 6 验收与切片

| 场景 | 预期 |
|---|---|
| 创建成功，领星未同步 | 货件可见，显示待同步 |
| 一个计划三张货件 | 三条实际货件正确关联，不合并成一条 |
| 两店铺同 SKU | 不串货件、数量和数据权限 |
| 缺实际发货量 | null，不能用申报量冒充 |
| 同步部分失败 | 保留旧数据并提示覆盖不完整 |
| 重复分页/事件 | 不重复计数，真实独立事件不误合并 |
| 平台关闭但有未结案件 | 异常仍可跟进 |
| 无领星入库字段 | 明示未取得，不伪装为已可售 |
| 页面操作 | 不出现确认发货/到仓/收货按钮 |
| 下载越权标签 | 后端拒绝 |

切片：领星来源与字段契约 → 同步及读模型 → 只读 API → 货件/商品视图 → 标签与异常关联。回滚页面功能开关或重建读模型，不删除原始证据和已创建货件。

待确认：领星准确接口及字段覆盖、运输节点含义、关联唯一性、刷新频率、历史与外部货件范围、性能目标。未核实前不得填造正式来源表或承诺真实接口可用。
