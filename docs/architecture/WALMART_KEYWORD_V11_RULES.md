# Walmart 关键词系统 · V1.1 规则重构（审查与工程基线）

> 状态：**待业务审批 / 可供安全基础设施开发**，不是已发布的 V1.1 投放规则。
> 来源：`广告投放正式版V1.0(4).md`（49 章，4036 行）；Walmart Ads V1 规则审计附件（2026-10-23）；本地差异附件（上传的 `git diff origin/main`，未包含 untracked 文件源代码）。以下规则正文及决策状态不因文件名表述调整而改变。
> 实施目标：**真实数据、不可变来源、逐词一次分析、多来源词库、后端版本化规则、正式文件二次确认、未来可扩展到广告自动入库/自动创建。**
> 安全边界：没有生产写入授权；不迁移、不部署、不调用真实广告创建接口。

## 0. 决策状态与四类约束

| 级别 | 意义 | 谁能修改 |
|---|---|---|
| I（不可妥协） | 原始证据不得伪造；失败不冒充成功；授权/账户隔离；结果来源可追溯；不能未授权写真实广告 | 开发者不可绕过 |
| P（平台约束） | Walmart API、当前账户权限、当前 Bulk Template 的必需字段/合法格式、实际出价范围 | 平台接口契约变更后重新核验 |
| B（业务策略） | P0/P1/P2 阈值、配额、Exact/Broad 选择、规则默认出价/预算 | **发布新版本**生效，旧 run 不回写 |
| U（展示/导出） | UI 11 列、Excel 14 列、5 Sheet、工作表排序、提示 A 列 | 通过独立模板版本变更 |

**禁止**把 B 类 Exact≤20、Broad≤20、配额和固定默认出价宣称为 Walmart 通用技术上限。当前 V1 可锁定这些限额进行业务验收；新版本可按审批调整。即使规则可配置，某次运行也不能突破其绑定的已发布版本。

## 1. 数据来源与商品确认（原章 5–9、14；审查稿 §1、§4、§6）

| Rule ID | 必须满足的契约 | 不符合的处理 |
|---|---|---|
| `PRODUCT-001` | 当前项目的 `products.id` 选择 SKU；选择真实 Walmart Item ID；后端核实所选 Item ID 与目标商品的关系，保存身份验证结果与证据 | `item_verified=false`；禁止「确认参数」 |
| `PRODUCT-002` | Walmart API/采集**只填写确实返回的字段**，未返回的字段为空。不得用 SKU、标题想象材质/Pack/尺寸/结构 | 空白+人工补充入口，保留来源 |
| `PRODUCT-003` | `title/item_type/brand/material/color/pack/size/structure/use/owner` 必填；禁止 `待核对/未知/N/A/--` 等占位文字冒充事实 | 不能确认，前后端双重拒绝 |
| `PRODUCT-004` | 用户可补充或修正真实商品事实。逐字段保存 value、source=`walmart/operator/product_management`、evidence_ref、确认人和时间 | 未核对项保留草稿，不自动认可 |
| `PRODUCT-005` | 「附加风险/禁止方向」不能空白直接意味着安全。运营须显式选择 `提供具体限制` 或 `已检查，无额外限制`；内置硬风险依然有效 | 未明确核对前阻断确认 |
| `PRODUCT-006` | Walmart 身份识别失败 ≠ 可以仅凭运营输入视为平台验证通过 | 默认不得最终确认；如以后允许纯人工核验，另建授权流程和证据校验，不能自动降级放行 |
| `PRODUCT-007` | 页面快照与运营确认事实**分开保存**。人工确认用途只能证明商品适配性，不能证明网页 Title/Features 已经埋词 | `page_evidence_missing`，不能展示已埋词 |
| `PRODUCT-008` | 商品、规则、Item ID、文件、ASIN 来源、确认字段任何评分相关变更 → 失效已有运行确认；新建 run，不篡改旧 run | 禁止从旧 run 直接正式导出 |

**Walmart 采集状态区分**：`verified`、`partial`、`failed`、`mismatch`。`partial` 只说明部分页面字段可得；必须另有有效的商品身份验证证据才允许 `item_verified=true`。真实图片中没有证据的商品属性仍应标为人工确认，而非页面证实。缺字段 ≠ 商品一定没有该属性。

## 2. ASIN 与图片（原章 8、14；用户后续确定）

- ASIN 必须是严格 **10 位大写字母/数字**；解析失败不得仅凭「非空」通过。
- 每次 Amazon API 抓取保留一条 `raw_kw_asin_snapshot`；响应 Title、Brand、Features、Description 原样留存，并指向完整原始响应对象。
- 每个 ASIN 快照的所有图片 URL 存入 `raw_kw_asin_image`，用 `image_index` 保存原始顺序，允许几十个/更多 URL、不同尺寸版本、甚至相同 URL 在原始结果中重复。
- ASIN API 数据只代表 Amazon 竞品，不得冒充 Walmart 商品事实、实际广告 CPC/ACOS，也不能凭 ASIN 反向定义本品材质/Pack。
- ASIN 历史快照与 SKU ASIN 关联 (`biz_sku_asin_reference`) 分离：当前关联能改变，但旧分析引用的是旧快照。
- 图片 URL 可能失效；可经合规授权和媒体缓存模块另行处理，**URL 本身必须完整保存**。

## 3. Excel 原始留存与去重（原章 6–7；用户后续确定）

| Rule ID | 必须满足的契约 |
|---|---|
| `UPLOAD-001` | 每次上传原文件原封不动保存到私有对象存储，记录 `sha256/object_key/uploader/size/parser_version/time`。同一文件再次上传也是新上传记录 |
| `UPLOAD-002` | 每个工作表及每条原始数据行保存到 `raw_kw_upload_row`，包括重复行、解析错误、来源坐标，绝不先删除重复行 |
| `UPLOAD-003` | **分析候选集**和**SKU 词库**在独立阶段做保守标准化去重：`trim + casefold + whitespace collapse`。不要擅自合并复数、拼写/词序、连字符词、同义词 |
| `UPLOAD-004` | 正式 SKU 词库具有 `(product_id,term_id)` 唯一约束；并发插入必须以 DB 原子唯一性和 `ON CONFLICT` 保护。重复只补充**来源事件**、**市场观测**，不覆盖人工备注或发布分数 |
| `UPLOAD-005` | 月搜索量、购买量、PPC 等指标按观测源+时间保存；无可比口径时不取最大值伪造“最真实”数据。只在已发布聚合策略下生成本轮代表值，保留所有原值 |
| `UPLOAD-006` | 导入无需让用户选择去重处理方式；前端只显示必要的上传状态和错误，不把大量去重统计作为用户确认步骤 |
| `UPLOAD-007` | Excel 原始数据是**不可信输入**，不得执行公式/宏；导出要防公式注入。上传后必须在后端重新校验，不以浏览器解析为权威 |

**原 V1 文档第 7.3 节“重复行取最大月搜索量/点击量”需调整**：允许在可比、同一统计期、同一平台和报表粒度条件下确定性聚合；否则保留冲突、标为不可直接评分或按明确的新规则选单一可信来源，不能掩盖来源差异。

## 4. 关键词类型、品牌和硬风险（原章 13、24、29–32）

- 保留原文 **25 个主类型允许值**作为外部展示契约；一个词内部可包含多个辅助标签。优先级先风险、已确认品牌，再常规本体/材质/规格/长尾等。
- 机器/设备词、配件/替换词、材质/尺寸/Pack/结构冲突必须有**结合该商品的证据**才能确认为硬风险；禁止仅按通用单词出现即全局封禁。
- **品牌已确认清单**、**疑似品牌候选**和**本品品牌**必须分开。品牌完整 token 命中已确认名单才入品牌等级；未确认疑似词进候选复查、不进入正式上传。
- 硬风险、明确虚假属性以及未证明的合规/认证声明**禁止**进入 Exact、Broad 和 Listing。01 风险数据和 03 风险清单不是自动否定词执行指令。
- 类型/风险没有足够证据时，输出 `人工确认词`/`候选复查` 和具体缺失依据，禁止借一个默认分数算作“已完成分析”。
- 核心词根必须是**真实产品语义实体/已验证同义词与变体**，不是简单截取英文前两词。`coasters for drinks` 不能以 `coasters for` 作为核心词根。

## 5. 页面承接（原章 14、28、34）

原 V1 UI 的九种允许值保留作为展示映射，但后端输入分为三类：

1. `product_fit`: 商品真实相关性，来源于被确认的商品事实及其证据。
2. `page_text_coverage`: 是否确实存在 Title/Features/Description/Attributes 对应短语，必须关联 `raw_kw_walmart_page_snapshot` 中原文片段位置；采集失败不能标为埋词。
3. `listing_recommendation`: 未埋词是否值得优化，禁止把“建议优化”当成“已埋词”。

显示等级对原 V1 使用以下九值：标题已埋词、标题意思已覆盖、详情/属性已埋词、场景/用途能接住、用户确认能接住、页面没埋但可优化、页面埋得弱先验证、页面看不出来、页面不建议埋。**“看不出来”不能等价为“商品不相关”。**

## 6. 评分与证据完备度（原章 15–16）

原始结构沿用为**待最终审批的 V1 评分框架**：

`score = clamp(0, 100, match[0,30] + intent[0,20] + page[0,20] + root[0,15] + data[0,15] + risk[-40,0])`

| 项 | 当前工程规则 | 尚需业务确认 |
|---|---|---|
| match / intent / root | 使用类型、商品事实、搜索意图、真实词根的确定性分档，记录来源 | “完全等于”“强/中/弱”等语义标签的**可执行条件和黄金样例** |
| page | 按九级映射 20/18/16/14/13/10/8/4/0；页面文字状态必须有真实页面片段 | 用户确认能承接时，页面证据缺失情况下允许的 Exact 测试范围 |
| data | 市场相对分位、购买量、PPC 等辅助信号；缺失单独建状态 | 原 V1 缺失项可拿 2 分甚至高于低表现的 1 分。建议先设 `unknown`，禁止“证明已优质”，待审批缺失分策略 |
| risk | 明确硬风险不依赖 40 分扣分救回 | 异常材质/Pack/认证证据边界需分类器测试样例 |

**本交付的安全规则组件不会自由生成六个分量**：它接受上游已明确验证的分量，缺少任何核心分量就标 `候选复查/score=null`，不制造缺失市场数据、页面埋词或出价。**这不是完整 25 类自动分类器。**

## 7. 双层等级和名额（原章 17–21、38）

| 字段 | 定义 |
|---|---|
| `base_grade` | 原始分数真实等级：P0≥85；P1≥75；P2≥60；候选复查≥45；不投放<45；硬风险覆盖 |
| `allocation_grade` | 按本轮 P0≤5/P1≤10/P2≤30 **容量分配**后的级别，溢出逐级下移；不得改写 `base_grade` |
| `exact_selected` | 严格候选准入后，依 P0→P1→P2 补位 raw≤20，不足可少、不用风险词凑数 |
| `broad_selected` | 与 Exact **独立判断**，最多 5 个词根 + 15 个安全长尾；需要词根角色/扩词风险证据；不足不凑数 |

配额是当前**业务策略版本**，不是平台绝对限额。最终池顺序必须稳定；原 V1 `§17.5` 14 层比较顺序实施时应逐层写可测试排序键（相同值按标准化关键词字母顺序）。

## 8. 建议价与广告执行价（原章 22–23、33、36–37）

- `suggested_optimization_bid`：01 市场分析参考建议价，依据来源明确的区间/PPC/已采集 Walmart Ads 数据，缺乏可靠参考时留空并标原因。
- `launch_bid`：04 执行方案中的广告出价，取本轮**已发布规则版本**；不许把 Amazon PPC 直接冒充 Walmart 平台建议出价。
- 同一 run 的出价、预算、广告命名、启动日期来源明确，`America/New_York` 计算当地日期，存 `YYYY-MM-DD`，模板确需 `MM/DD/YYYY` 时仅在导出转换。
- 04 原模板要求 Suggested Bid、Total Budget、Item Name 整列空白应**按实际被确认模板版本检查**；现在不能预设当前 Walmart 模板永远使用某套字段。
- 自动创建广告是**未来独立授权流程**；`ai_kw_rule_version(rule_type='ad_creation')` 仅预留配置，不能因为关键词入库就触发创建。

## 9. 统一分析结果 → 前端/五表（原章 10–12、25、32–36）

**单一数据源是 `ai_kw_run_keyword` + 对应已冻结 run/事实/ASIN/页面/规则快照，而不是 01 Excel 文件。**

- 前端「投放决策」的 **11 列**从同一 run 投影：关键词/中文、类型、页面承接、核心词根、词质说明、潜力分、等级、Exact、Broad、建议出价、未入选原因。
- 01 Excel 固定 **14 列**（原文当前模板），不要用 UI 11 列覆盖它；每个关键词只产生一条本轮分析行。
- 02 词根 Broad：从本轮关键词结果分组聚合，保留 root/long-tail 角色及各自未入理由；不能重新评分类别。
- 03 风险：引用同轮风险结果，仅作人工隔离决策，不等于自动否定词。
- 04 广告结构：只从被选中的投放目标与已确认执行参数映射，并执行模板版本/空列/列顺序/日期检查；**分析版提示 A 列不能混入纯官方上传版**。
- 05 Listing：只基于真实商品事实 + 同轮关键词结果做优化建议，不反向改写分数与投放等级。
- Excel 表格的格式、冻结、筛选、样式属于模板配置；正式导出前须通过格式检查。

## 10. 生成确认与安全回路（原章 5、42–48）

`sku/item_id verified` → `fact fields complete` → `original excel captured` → `ASIN evidence captured` → `published rules bound` → `run complete` → `user final approval` → `template verified` → `self-check passed` → `official output`。

`确认参数` 是**输入事实与运行参数**的确认；`生成正式上传文件` 要求用户再对本 run 的实际结果与上传范围显式确认，不等同于选择 Excel / Item ID 后授权。

必须保留 `run_id, input_sha256, rule_version_id, parser_version, normalizer_version, engine_version, approval actor/time, export_template_version`。`run` 已完成后不得原地覆盖，变化则创建新的 run。

## 11. 未来自动入库和真实广告（用户已确定，原文未覆盖）

- Excel、运营后台手动投放、自动广告出单搜索词、系统未来创建广告是**不同来源事件**；SKU 词库同词仍只能一条。
- 自动广告 Search Term ≠ 手动 Exact/Broad Target；原始未入库搜索词全部保留，符合发布的 `search_term_admission` 规则才自动加入词库，拒绝原因也记录。
- 仅入词库不等于创建广告。真实执行须店铺/账户范围、权限、配额、幂等键、重试与平台再核对；不能靠连接同一网络出口认定多店铺没有关联风险。
- 现阶段只建 `ai_kw_rule_evaluation` 和 `biz_kw_source_event` 为未来留证据；广告对象/日报/执行任务 12 张表按阶段二单独迁移，**本 V1.1 迁移不创建也不发广告**。
