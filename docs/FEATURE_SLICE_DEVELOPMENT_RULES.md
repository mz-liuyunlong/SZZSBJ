# 单功能切片开发规则

## 文件用途

本文件用于约束 AI 在本项目中开发新功能时的任务边界。

本项目后续必须采用“单功能、单页面、单闭环”的开发方式，避免 AI 一次性生成过多代码导致不可维护。

## 核心原则

每次 AI 开发必须遵守：

1. 一个任务只做一个功能。
2. 一个任务最多只做一个页面。
3. 一个任务只允许影响一个业务模块。
4. 一个任务只允许建立必要的最小前后端闭环。
5. 一个任务必须可以独立测试。
6. 一个任务必须可以独立回滚。
7. 一个任务必须单独建分支。
8. 一个任务必须单独提交 PR。

## 推荐开发粒度

正确任务示例：新增广告活动列表页面、新增广告搜索词列表页面、新增否定关键词管理页面、新增产品管理列表页面、新增订单利润报表页面、新增退款管理列表页面。

错误任务示例：一次性完成整个广告系统、一次性完成产品销售财务三个模块、一次性生成全部菜单页面、一次性重构前端布局和后端接口、一次性重建 old-system 的所有功能。

## 单页面任务允许修改范围

前端可修改当前页面文件、页面专属组件、页面专属 hooks、types、API client、相关路由与菜单配置。

后端可新增或修改当前页面对应的 API route、Pydantic schema、Service、Repository、必要查询逻辑和测试。

数据库只有在当前页面确实需要新表或新字段时才允许涉及，必须先说明原因并等待用户确认。

## 禁止范围

开发一个页面时，AI 不允许顺手修改其他业务模块、其他页面、全局架构、全局权限、全局 API 返回结构、数据库基础设计、Celery 基础配置、登录认证体系、`old-system/` 目录、无关公共组件、无关依赖版本。

如果 AI 认为必须修改公共代码，必须先说明原因并等待用户确认。
