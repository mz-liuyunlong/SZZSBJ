# 单功能切片开发规则

## 文件用途

本文件用于约束 AI 在本项目中开发新功能时的任务边界。

本项目后续必须采用“单功能、单页面、单闭环”的开发方式，避免 AI 一次性生成过多代码导致不可维护。

## 核心原则

每次 AI 开发必须遵守：

1. 一个任务只做一个功能。
2. 一个任务最多只做一个页面。
3. 一个任务只允许影响一个业务模块。
4. 一个任务只允许建立必要的最小前后端闭环。
5. 一个任务必须可以独立测试。
6. 一个任务必须可以独立回滚。
7. 一个任务必须单独建分支。
8. 一个任务必须单独提交 PR。

## 推荐开发粒度

正确任务示例：

- 新增广告活动列表页面。
- 新增广告搜索词列表页面。
- 新增否定关键词管理页面。
- 新增产品管理列表页面。
- 新增订单利润报表页面。
- 新增退款管理列表页面。
- 新增库存预警页面。
- 新增 AI 优化记录页面。

错误任务示例：

- 一次性完成整个广告系统。
- 一次性完成产品、销售、财务三个模块。
- 一次性生成全部菜单页面。
- 一次性重构前端布局和后端接口。
- 一次性重建 old-system 的所有功能。

## 单页面任务允许修改范围

当任务是“开发一个页面”时，AI 可以修改以下内容。

### 前端允许修改

- 当前页面文件。
- 当前页面专属组件。
- 当前页面专属 hooks。
- 当前页面专属 types。
- 当前页面需要的 API client。
- 当前页面相关路由配置。
- 当前页面相关菜单配置。

### 后端允许修改

如果页面需要后端数据，允许新增或修改：

- 当前页面对应的 API route。
- 当前页面对应的 Pydantic schema。
- 当前页面对应的 Service。
- 当前页面对应的 Repository。
- 必要的数据查询逻辑。
- 必要的测试文件。

### 数据库允许修改

只有在当前页面确实需要新表或新字段时，才允许涉及数据库。涉及数据库时必须先说明原因并等待用户确认。

## 禁止范围

开发一个页面时，AI 不允许顺手修改：

- 其他业务模块。
- 其他页面。
- 全局架构。
- 全局样式体系。
- 全局权限逻辑。
- 全局 API 返回结构。
- 数据库基础设计。
- Celery 基础配置。
- 登录认证体系。
- `old-system/` 目录。
- 无关公共组件。
- 无关依赖版本。

如果 AI 认为必须修改公共代码，必须先说明原因并等待用户确认。

## 完成标准

一个页面任务完成后，必须具备：

1. 页面能打开。
2. 路由能访问。
3. 页面标题明确。
4. Loading 状态完整。
5. Empty 状态完整。
6. Error 状态完整。
7. 表格有分页。
8. 筛选条件清晰。
9. 类型定义明确。
10. API client 已封装。
11. 必要代码有维护型注释。
12. 没有修改无关模块。
13. 没有修改 `old-system/`。
14. 有测试或构建检查结果。
15. 有回滚说明。
