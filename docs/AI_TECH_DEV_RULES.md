# AI 技术开发规则

## 文件用途

本文件用于约束 AI 在本项目中的技术实现方式。

## 总原则

AI 必须：

1. 遵守固定技术栈。
2. 先复用已有模式，再新增方案。
3. 先做小范围修改，再考虑抽象。
4. 不自行更换技术栈。
5. 不新增第二套架构。
6. 不随意新增依赖。
7. 不把业务逻辑堆在页面或 API Route 中。
8. 不复制 `old-system/` 代码。
9. 新增代码必须有维护型注释。
10. 完成后必须说明风险和测试结果。

## 前端重点

- 页面负责组合。
- API 请求必须封装。
- 类型必须明确。
- 优先使用 Ant Design / ProComponents。
- 多页面重复 UI 必须考虑通用组件。
- 不允许前端直接调用敏感外部 API。

## 后端重点

- Route 保持薄。
- Service 写业务逻辑。
- Repository 写数据访问。
- Integration 写外部 API 客户端。
- Task 做 Celery 任务编排。
- Model / Migration 必须一致。

## 新依赖规则

新增依赖前必须说明：

1. 为什么现有依赖不能解决。
2. 新依赖解决什么问题。
3. 是否长期维护。
4. 是否影响构建体积。
5. 是否有安全风险。
6. 是否可以不用新增依赖实现。

未获确认前，不得新增依赖。
