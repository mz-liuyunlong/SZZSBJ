# 代码注释规则

## 文件用途

本文件用于约束 AI 如何写维护型注释。

本项目要求代码能被后续开发者和 AI 理解。注释不是越多越好，而是要解释业务含义、设计原因和维护注意事项。

## 注释总原则

好的注释解释：

- 为什么这样做
- 业务规则是什么
- 边界条件是什么
- 哪些副作用需要注意
- 哪些地方未来变更要同步

不要写只是翻译代码的注释。

## 必须写注释的位置

| 位置 | 要求 |
|---|---|
| 新文件顶部 | 说明文件职责和不负责什么 |
| 后端 Service | 说明业务逻辑、输入、输出、关键规则 |
| Repository 复杂查询 | 说明查询目的、筛选条件、性能考虑 |
| Celery 任务 | 说明任务目的、幂等性、重试策略、副作用 |
| SQLAlchemy Model | 表职责和重要字段含义 |
| Alembic migration | 说明为什么变更表结构 |
| Pydantic Schema | 重要字段使用 description |
| React 页面 | 说明页面职责和数据来源 |
| 自定义 Hook | 说明封装的逻辑和返回值 |
| Zustand Store | 说明状态用途和作用范围 |
| 金额计算 | 说明币种、公式、是否含退款/广告/运费 |
| 时间计算 | 说明时区、平台时间还是系统时间 |
| 外部 API 调用 | 说明接口来源、超时、失败处理 |
| AI Prompt | 说明版本、用途、输入输出 |

## 禁止无意义注释

不要写：

```ts
// 设置 loading 为 true
setLoading(true)
```

应该写：

```ts
// 保留最近一次筛选条件，方便用户从详情页返回列表时恢复原查询状态。
setLastQuery(query)
```

## Python 示例

```python
class OrderProfitService:
    """
    订单利润计算服务。

    职责：
    - 汇总销售收入、商品成本、物流成本、退款金额和广告分摊成本。
    - 输出页面和报表可直接使用的利润结果。

    维护提示：
    - 金额字段必须明确币种。
    - 退款规则变更时，需要同步更新测试用例。
    """
```

## Celery 任务注释要求

每个 Celery 任务必须说明：

1. 任务用途。
2. 输入参数。
3. 输出结果。
4. 是否幂等。
5. 重试策略。
6. 会修改哪些表。
7. 是否调用外部 API。
8. 是否可能产生费用。
9. 失败后用户应该看到什么。
10. 是否允许重复执行。
