# WooCommerce catalog / rules — deployment code slice

Authority: saved verified store credentials in sys_woocommerce_stores. External read-only WooCommerce product/currency endpoints -> sanitized RAW field allowlist -> DIM. No arbitrary plugin metadata, credentials, or passwords. Currency must be observed from the store settings; source date is UTC and never assumed to be publication date. A completed full scan marks absent products missing without deleting the row or evidence. Incremental reads only advance on a successful frozen window; deletion/older changes are reconciled by a periodic full scan. Catalog sync has a bounded 5000-product per-store fetch and per-attempt timeout; a limit or inconsistent pagination fails without publishing partial data. No fabricated comparison prices or offers, no external product writes or submission automation.

Exact confirmed mapping uses existing Walmart account + store + item identity, never a SKU heuristic. WooCommerce product page, Listing Management and New Product Performance share the same mapping/DIM facts. Listing and New Product tables look up a batch of visible identities, with no per-row upstream reads. Missing mapping stays missing. Store credential setup and existing Task Center action/data permissions remain unchanged. Per owner instruction the Woo product page and its rule configuration require authentication only, not a dedicated page permission or product account scope; credential values never leave the server. All rule saves retain optimistic version checks and audit.

Read model uses server-side filtering, count, stable ordering, offset/limit. Description-specific filter parses candidate short descriptions on the backend for exact five-point semantics; does not fetch every product to the UI. Brand/shop dropdowns come from the local DIM/store tables. Task center uses existing interface/config/run/work item/event/lease tables and Integration queue; manual full, scheduled incremental with 10-minute overlap and full reconciliation at least every seven days, retry uses the failed window, up to three transient attempts. Catalog and run success are committed atomically under a verified lease. Scheduler is default off; existing-store registration CLI after owner migration, and registration on subsequent store config edits. No new migrations beyond the owner's Woo 0102/0104, no changes to other revision files. Deployment must validate actual database, full project CI, task-center registration, real upstream incremental parameter compatibility and cross-page render. If upstream rejects or ignores the window, fail closed and retain the previous catalog.
