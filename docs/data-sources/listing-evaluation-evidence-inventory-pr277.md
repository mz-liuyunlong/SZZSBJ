# Listing 生命周期与评级证据清单（PR #277）

状态：**DRAFT / READ_ONLY_EVIDENCE_AUDIT**。2026-10-31 核对当前分支的源码、模型及现有数据源决策，并对生产数据库执行了限时、只读、只返回聚合的复核；未调用旧系统或外部 API。生产业务日期、数量和金额不写入公开仓库，现场聚合结果另行向负责人报告。表存在、字段存在、代码能够查询，均不等于历史数据覆盖完整或业务权威已批准。本清单不批准正式评级、生命周期写回、Listing 正式评级调度启用或迁移。

## 负责人后续口径（2026-11-02）

- 本轮评级与生命周期只覆盖 WFS；FBM 不参与。预览对非 WFS 不产生评级或阶段候选，不以 WFS 库存推断 FBM 断货。普通 Listing 浏览不因此排除 FBM。
- 销售业务日结束后，美国时间次日 00:00 的最后一次查询必须成功，才能把该日无销售记录认作真实零销量；仅凭时钟到点或空结果不算完整。每次评级以洛杉矶执行日的 T-2 为截止业务日，直接使用“每日销售”已计算的多日销售额和利润。广告费和退款由每日销售处理，评级模块不再单独查询广告或退款，也不另建迟到退款重算门禁。
- 广告完整性信号读取领星广告报表接口已入库的同账号、同 LA 业务日全部行；只有全部广告费为零或没有行才阻断，不按当前 SKU 单独判断，也不让 SEM 费用代替该接口的完成信号。每日销售缺少次日 00:00 后的日级同步完成事件时同样不生成评级候选；旧运行没有新事件时保守阻断，不补造完成证明。
- 人工生命周期调整优先于自动计算；需要权限、操作人、原因、时间及审计。负责人希望证据齐全后自动生效、执行时间可配置；本文件不批准在证据不齐或人工调整未受保护时启用正式发布与生产调度。
- Listing 页的“上架时间”仅指**开始监测新 Listing 后首次观察到 WFS 库存至少为 1 的日期**，来源为 `listing_wfs_first_stock.launch_date_cn`，其观察时间记录在 `first_wfs_seen_at_utc`。已入监测但首次零库存的 Listing，即使随后 MART 出现旧来源日期，也继续等待首次 WFS 有货观察。旧 Listing 没有该证据时显示待核实；ERP 原始上架日期和标准化字段仍保留为来源数据，但不作为页面上架时间的兜底，不进行时区猜测或回填。
- 负责人于 2026-11-03 选择从上线后记录 WFS 每日采集完成标记；旧日期无标记保持未知。该库存标记与每日销售的零销量完成事件分别证明不同事实，不能互相代替。当前 Listing 库存日按整批写入日期赋值，分页抓取时间可能跨 LA 午夜且短页尚未核对提供方总量；实施标记前必须解决这些证据缺口，正式写回仍待获批 PRP。
- 负责人确认页面标签是人工维护。当前既有人工分配表与 MART 保留的历史 `tags_json` 均可能承载人工标签；`tags_json` 的逐条来源尚未核定，不能直接隐藏或删除历史值。跨店铺同 Item ID 是否共享仍待负责人确认，现有赋值粒度暂不改变。
- GPT 功能目前仅保存分析链接；列配置跨设备持久化暂缓。产品启停、产品类型、平台状态筛选暂缓，不将既有混合口径视为已修复。

## 1. 核对范围与共同口径

- Listing 当前身份：`source_account_ref + store_id + item_id`，来源 `mart_listing_management_current`；日销售 MART 与库存 FACT 还使用可空 `msku` 做精确匹配。不能以 SKU、MSKU 或 Item ID 单独推断归属。
- 时间：评级代码按 LA 业务日的执行日减两天确定截止日；多日评级窗口不超过该截止日。T-2 不等于每日销售同步成功，评级只检查每日销售自身的完成和成本状态，不另接广告或退款表。
- `null`、缺行、同步失败、已确认的零，是四种不同状态。没有独立完整性证明时，一律不把缺行补为零。
- 状态列：`源码可读`只说明字段/查询已存在；`证明缺失`说明尚不能正式发布；`待负责人决定`说明权威来源或业务含义未批准。此处没有一项标为“生产数据已认证”。

## 3. 需要用真实数据补的核验（只读，需单独授权）

| 核验 | 只输出的安全聚合 | 合格条件 / 失败处理 |
|---|---|---|
| Listing 身份与账号隔离 | 当前行数、稳定键重复数、空键数、可见账号数量 | 重复或空键先修身份；不输出账号或商品明细 |
| 销售日覆盖与零销量 | 截止日前 14/30 日按日期的预期对象数、已收到数、明确零数、缺失数、失败数 | 缺失与明确零必须分开；未有采集完成水位则不得认证零日 |
| 每日销售完成状态 | 按 LA 日的最新 pending/validated 事件、结果行数、`cost_status`、缺成本代码及利润空值数 | 仅次日 00:00 后验证完成的日期可进入试算；旧运行缺事件保持未知，成本未完成或利润未知的日期无效 |
| 退款（质量观察，不是本轮单独发布门禁） | 按 LA 日的同步完成、未匹配、缺币种与迟到变更数 | 记录来源质量及对既有利润的影响；不因迟到数据自动撤销历史评级 |
| WFS/FBM 库存 | 每日应有快照数、实际成功数、真零数、缺快照数、FBM 来源覆盖数 | FBM 来源未获证实前单独保持未知；缺快照不补零 |
| 历史流程 | 有时间戳的初始化、审批、断货、恢复、归档／恢复事件覆盖数及冲突数 | 不可从当前状态合成历史事件；无法回放则历史结果保持诊断 |
| 版本与权限 | 生效规则版本数、无版本计算数、未发布快照数、跨账号拒绝测试结果 | 未发布快照不得被前端解释为正式评级；权限从后端校验 |

以上是验收**方法**。本轮已按只读事务、查询时长限制和聚合输出约束执行其中一部分；它们不是已经通过的完整性认证。后续复核仍需按账号权限执行，只返回聚合；不输出账号标识、商品标识、标题、URL、payload 或密钥。

### 本轮现场证据结论（公开版）

- 当前 Listing 稳定业务键无重复或空值；正式生命周期和等级字段仍未填充。身份质量通过不代表阶段、等级来源已获批准。
- 最近业务日的销售、广告和库存数据存在，但库存日覆盖有缺口；销售日出现不完整信号，缺少足以认证真实零销量的采集水位。
- 广告事实存在未归属店铺的记录；相关同步任务有失败记录。这是每日销售上游质量风险；评级只消费每日销售已完成的结果。
- 退款数据分布在不同来源表；退款同步的近期成功水位不足，不能据单个来源表判断退款已经完整结算。这是利润来源的质量风险，不再作为本轮多日评级的独立阻断门禁。
- 监控标准化观察可用稳定业务键关联当前 Listing，但目前只覆盖部分 Listing 和业务日；尚未完成 RAW 投递及历史采集范围对账。
- 归档表主要反映当前状态，缺少可完整回放的历史事件；规则版本虽存在，正式计算运行和结果快照仍为空，不能证明发布链路已经闭环。
- 因此 E02–E05、E07–E09、E11–E12 仍未达到正式评级、历史生命周期写回或 Listing 正式评级调度启用门槛；E06 保留为数据质量观察，不作为单独阻断。继续保持诊断和未发布状态。具体聚合数字仅在本次私有会话中提供，不进入 Git 文档或 PR 正文。

## 4. 待负责人一次确认的决定

1. **每日销售完成状态**：哪个运行记录证明 T-2 业务日的每日销售同步和计算已经完成？评级直接读取其多日销售额和利润，成本状态不完整时显示“待评级”；不另查广告、退款数据。
2. **库存与零销售**：本轮仅覆盖 WFS；库存完成标记从上线后开始记录，旧日期无标记保持未知。零销售由每日销售独立的次日 00:00 后完成事件证明，不用库存标记替代。待获批 PRP 需确定库存事件与事实同事务、同 LA 日和分页总量校验。
3. **历史阶段**：首次上架、测品、清货、断货恢复、归档／恢复的权威事件在哪里？人工审批与自动规则谁优先？建议无历史事件时不正式回填历史阶段。
4. **发布边界**：在 E01–E11 全部达到可复核状态后，另行批准正式发布的权限、审计、冻结规则版本和回滚 PRP；生产调度仍需单独授权。

依据：`docs/data-sources/decisions/listing-evaluation-preview-decision.md` 当前是 `BLOCKED_BY_OWNER_DECISION`；项目数据分层及字段标准化规则要求源头、粒度、时间、币种和血缘可追溯。本清单不更改该决定状态。
