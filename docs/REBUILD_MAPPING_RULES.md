# 旧系统重建映射规则

## 文件用途

本文件用于约束 AI 如何把 `old-system/` 中的旧功能映射到新系统。它不是让 AI 修改旧系统，也不是让 AI 复制旧代码。

## 映射对象

AI 分析旧系统后，应输出以下映射：

| 旧系统对象 | 新系统对象 | 说明 |
|---|---|---|
| 旧页面 | 新页面 / 新模块 | 是否保留、合并或废弃 |
| 旧 API | 新 API 契约 | 路径、参数、返回字段如何重新设计 |
| 旧表字段 | 新数据模型 | 字段含义、类型、币种、时区 |
| 旧定时任务 | 新 Celery 任务 | 任务目的、频率、幂等性 |
| 旧业务公式 | 新 Service 规则 | 必须明确公式口径 |
| 旧导入导出 | 新导入导出任务 | 模板、校验、错误报告 |

## 重建原则

1. 只保留业务价值，不保留脏架构。
2. 不复制旧代码。
3. 不直接沿用旧命名，除非它本身是业务标准。
4. 涉及财务、库存、广告、退款的逻辑必须单独确认。
5. 旧功能是否重建必须明确：保留 / 合并 / 废弃 / 待确认。

## 输出模板

```md
# 旧功能重建映射：{功能名称}

## 读取文件

## 旧系统功能

## 旧系统数据来源

## 旧系统问题

## 新系统设计

## 字段映射

| 旧字段 | 新字段 | 类型 | 说明 | 是否保留 |
|---|---|---|---|---|

## API 映射

## 页面映射

## 风险和待确认问题
```
