# Listing 等级规则配置 V1.0 — 本地验收与业务 SOP

## 业务定位

Listing 管理页面右上「规则配置」打开抽屉，V1.0 的「等级评级」可编辑，另外「生命周期」「库存与修复」「运营跟进」仅展示后续实现说明。**配置保存并不启用评级引擎**，也不会更新 Listing 的现有等级或生成 C/D 日志。

### 规则及受保护字段

| 项目 | 默认值 | 允许修改 |
|---|---|---|
| 短/中期窗口 | 7 / 14 天 | 是 |
| 权重 | 60% / 40% | 是，合计 100% |
| 有效天数 | 4 / 8 | 是，不超过窗口 |
| 等级阈值 | 5 / 10 / 15% | 是，严格递增 |
| 参与阶段 | 打品、启动、上升、稳定、下滑、修复 | 是，测品和断货可选 |
| 永久排除 | 清货、已归档 | 否 |
| 评级时间 | 中国时间 22:30 | 否 |
| 销售业务时区 | America/Los_Angeles | 否 |
| 截止日延迟 | T-2 | 否 |
| 费用完整性 | 缺失费用不计入有效日 | 否 |

## 管理员操作

1. 进入「产品 → Listing 管理」，点击右上「规则配置」。
2. 检查当前版本（v0 为默认内置配置；v1 及之后为数据库保存版本）。
3. 调整规则参数，并填写至少 3 个字符的修改原因。
4. 保存将创建**新版本**，生效时间为下一次北京时间 22:30。未授权账号只读。
5. 在「变更记录」查看版本号、理由、操作人和计划生效时间。

## API（本地/测试环境）

- `GET /api/listings/rule-config`：现有 Listing 页面查看权限；返回最新**已保存**版本、是否待生效、受保护项、can_edit，以及服务端只读 `preview_enabled`、`scheduler_enabled`、`publish_enabled` 开关状态。开关状态不证明任务运行或正式发布已完成。
- `PUT /api/listings/rule-config`：需 `action:products:listing-management:configure-rules`；请求：
  `{"expected_version":0,"change_reason":"优化样本门槛","config":{"short_days":7,"medium_days":14,"short_weight_percent":60,"medium_weight_percent":40,"short_min_valid_days":4,"medium_min_valid_days":8,"c_min_percent":"5","b_min_percent":"10","a_above_percent":"15","included_stages":["打品期","启动期","上升期","稳定期","下滑期","修复期"]}}`
- `GET /api/listings/rule-config/history?limit=20&offset=0`：查看历史列表。
- 返回格式：统一 `success/data/error/meta/request_id`。
- 409：版本冲突或无参数变化；422：参数非法或试图提交受保护字段；403：缺少权限。
- **现有评级消费端尚未对接此配置 API**。当前接口不能被解释为已部署定时评级。

## 首次本地验证

先在隔离的本地 PostgreSQL 运行 Alembic 升级及 IAM 权限目录初始化，再启动后端、前端。**不得在生产数据库执行迁移**。

检查项：
- 权重总和不为 100%，短窗口大于等于中窗口、阈值乱序、有效天数超窗：拒绝保存。
- 清货/归档以及 timeZone、T-2 等受保护字段：拒绝通过 API 更新。
- 并发保存同一 expected_version：只能有一个版本成功。
- 旧规则版本不可被覆盖或删除；即使两次保存针对同一下一次 22:30，也保留变更历史。
- 真实角色权限阻止未授权写入；预览令牌不得获得规则配置写权限。
- 页面保留 Listing 原筛选/搜索、标签管理、列配置、下载功能。
- 无需领星真实调用、生产连接、历史回填或重新同步。

## 回滚 / 安全边界

采用新增版本回滚参数，不在生产环境删除已有历史记录。此 PR 不在生产运行迁移，不改 ERP「每日销售」利润，不更改生命周期引擎。
