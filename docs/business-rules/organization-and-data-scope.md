# 组织架构与数据权限规则

## 1. 为什么需要组织架构

运营系统中常见场景：

```text
普通运营只看自己的产品
小组长看自己和组员的产品
主管看整个部门的产品
老板看全部
临时账号看指定 SKU / 店铺
```

这不能只靠角色完成，必须加入组织架构、产品负责人归属和页面数据权限。

## 2. 三者分离

```text
角色 = 能做什么
组织架构 = 属于哪个组、管谁
数据权限 = 在某个页面能看哪些数据
产品负责人归属 = 哪些产品 / SKU 归谁负责
```

## 3. 数据权限模式

```text
all              全部数据
own              仅自己负责的数据
direct_reports   自己 + 直属下级的数据
team             当前小组数据
org_tree         当前组织及所有下级组织数据
selected         指定店铺 / 指定负责人 / 指定 SKU
custom           自定义组合
none             无数据
```

## 4. 页面可单独配置

同一个用户在不同页面可以有不同数据范围：

| 页面 | 数据权限口径 |
|---|---|
| 产品管理 | 主运营 / SKU |
| 每日销售 | 主运营 / 店铺 / SKU |
| 广告总览 | 广告负责人 / 店铺 / SKU |
| 采购计划 | 采购负责人 / 供应商 / SKU |
| 库存预警 | PMC 负责人 / SKU / 仓库 |
| 利润中心 | 财务授权 / 店铺 / SKU |
| API文档 | 系统权限，不走产品范围 |
| 用户管理 | 系统权限，不走产品范围 |

## 5. 产品负责人类型

`core_product_owner.owner_type` 建议支持：

```text
main_owner        主运营
ads_owner         广告负责人
purchase_owner    采购负责人
pmc_owner         库存负责人
assistant_owner   协助负责人
```

必须支持：

```text
start_date
end_date
is_active
```

用于处理产品转负责人和历史归属。

## 6. 负责人历史口径

默认：

```text
权限过滤：当前有效负责人
绩效 / 奖金 / 历史复盘：历史负责人
运营看板：可支持当前负责人 / 历史负责人切换
```

## 7. 后端过滤原则

数据权限必须由后端强制执行。禁止让前端通过参数决定是否看自己的数据。

错误：

```text
?only_my_products=true
```

正确：

```text
后端根据当前用户、当前页面、当前数据权限自动添加 WHERE 条件。
```

## 8. 页面展示

`PageShell` 顶部应显示当前数据范围，例如：

```text
数据范围：仅自己负责的产品
数据范围：自己 + 直属组员
数据范围：全部数据
```


## 9. PR #287 — 账号限定店铺权限的业务合同（代码提交，待验证）

**授权粒度**：必须精确匹配 `source_account_ref|store_id`，例如同一个
`store_id` 出现在不同 `source_account_ref` 时属于两个不同身份。
业务接口始终先收紧账号范围，再将店铺范围按二元组合键与组织负责人范围取**交集**，
不允许前端筛选参数放宽授权范围。

- `source_account` 由已登记同步账号与有效用户角色范围决定；
- `org_department` 由最新飞书快照、有效员工和明确人工审核的负责人绑定决定；
- `store` 的角色/用户持久化范围仍遵循“用户同类型覆盖角色”的原有模型；
- 未指定 `store` 时不增加店铺限制；包含歧义的历史裸 `store_id` **拒绝**而
  不是按全局店铺授权；
- 当前实现仅覆盖经过独立审查的每日销售、Walmart Listing 和 PMC 采购看板
  明细路径，包括这些路径的列表、统计、筛选与导出（有导出接口时）；
- 对尚未证明店铺归属安全的财务、广告、库存、通用商品变更与其他路由，
  不开启新店铺范围的授予；`RbacService` 仍对新 `store` 授权返回 422，
  直至所有受影响业务模块完成隔离与复核。

### PMC 采购的交叉归属保护

采购单号、库存与采购 SKU 不自动代表单一负责人或单一店铺。
采购板受限列表可展示经 SQL 证明归属的明细及其行级分配金额，
但整单金额、采购总量、整单收货结果、跨负责人历史交期与样本不可借明细授权获取。
相关受限响应的 `scope_limited=true` 明确区分“无归属证据”与真实数值零；
被隐藏的整单/历史数值序列化为 `null`，不填充模拟值。
未确认归属的 SKU 周期列表、人工修正以及交期卡片明细筛选仍拒绝访问。

上述实现未运行完整 CI、真实 PostgreSQL 或业务人工验收，
**不能据此认定全平台 `store` 数据范围已经完成并可配置**。
