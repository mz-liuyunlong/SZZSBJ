# 打品详情日期范围筛选

- 入口：产品 / 打品跟踪 / 打品详情，复用 `ReportDateRangePicker`（每日销售、新品表现相同中文双月日历）。
- 默认不限日期；从看板钻取时继承原区间，可调整或清空。日期调整回到第一页，保留负责人、初始评级、搜索和结果分类。重置清除区间及钻取条件。
- 继续使用既有 GET `/api/new-products/tracking/listings` 的 `from`、`to`（YYYY-MM-DD，闭区间）；两端同时传入或同时省略。后端 `tracking_read._projection` 的 `entry = arrival or launch` 为已存在的看板/详情统一口径：优先 WFS 首次可售日，缺失时使用既有 Listing 上架日；两者都缺失的商品仅在不限日期时纳入。不是历史时点的打品状态快照。
- 统计卡、负责人及初始评级数量、总数、分页由同一接口返回；原 30/60/180 天数据周期独立，不改评分、利润或打品判定。
- 来源与权限沿用现有接口：`scoped_projection` 及 `_saved_decisions`，账号范围、MART、已保存决策；没有新增数据字段、数据表、外部调用或写操作。
- 验收：不限日期、单日、快捷日期、清空、翻页、分类切换、看板钻取和重置，验证 Network 中仅原列表接口及 from/to 参数。完整联调与 CI 待执行。

## 打品详情加载交互

- 仅打品详情列表查询使用 `runWithoutBackendRequestBusy`，不影响其他查询及写操作的全局忙碌状态。
- `ProTable.loading` 使用列表请求的 `isFetching`；保留现有 `keepPreviousData`，不在表格上方插入加载文字。
- 请求期间保留筛选、日期范围、统计卡及表头结构；旧数据不能用于打开操作抽屉。成功后使用新数据，失败仍显示原有错误提示。
- 现有 `from/to` 参数、缓存键、分页、权限、统计周期和业务计算不变。
- 验收：首次进入、选择日期、切换统计卡、快速连续筛选、翻页、清空及请求失败；确认筛选栏可继续操作，表格内部显示加载状态，页面不因加载文字发生位移。
