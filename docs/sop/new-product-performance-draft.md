# 新品表现 / 打品跟踪 — PR #278 开发验收 SOP

适用环境：未上线的测试/开发页面，PR #278 Draft，禁止生产采购、生产数据库迁移和真实同步。

1. **新品表现**：在产品导航进入新品表现。Mock 明细和看板用于核对搜索、列宽、审批弹窗和统计卡样式；模拟计划不会生成采购单。
2. **打品跟踪**：查看 Mock 明细和看板的状态、复盘与 30/60/90 天交互。此视图不代表正式出单/利润或真实成功率。
3. **正式数据**：切换正式数据 Tab，选择后端按权限返回的来源账户，再点击加载真实数据；用户不能任意注入其他账户。
4. **经营指标**：查看各周期实际覆盖天数、缺失日数、广告花费与归因 ACOS、财务币种及不完整原因；空值不是零。无利润字段授权则服务端遮蔽利润/利润率及衍生评级。
5. **可售起点**：有复盘权限人员确认实际到货日、可售日与可追溯依据；未来日不得作为实际日期。观察期以两日期较晚者起算。
6. **采购申请**：提交有原因的独立新品采购草稿，审核批准后同事务写入 `product_new_purchase_plans` 独立计划、审批状态和审计事件；计划编号、数量、审批依据与规则版本保留不可变快照。计划 `approved / not_executed` **不表示供应商下单、已付款、已采购或已入库**，且不调用 PMC。
7. **异常处理**：如数据天数不足、归因币种空缺、跨账户失败或规则未批准，记录 SKU/来源账户/业务日及请求 ID，提交代码审查，不自行改原财务数据。
8. **验收**：分别审 Mock 样式和正式数据；Playwright/pytest/Vitest/CI 证据必须对应最新 Head；人工验收由负责人确认。

参考 `docs/api/new-product-performance-draft-v1.md`。
