# 国内仓打包单审批本地操作说明

## 2026-10-28 当前功能补充

以下规则覆盖后文早期说明中对应旧行为。当前为本地代码修改，尚未完成真实数据联调；负责人已要求暂停测试。

1. 商品必须完成 WFS 转换才可审批。列表显示“待补资料”时查看具体原因；“尚未完成 WFS 转换”需先在对应平台完成转换，再通过现有同步更新 Listing 并刷新候选。本页面不执行转换。待补资料不等于已驳回。
2. 多 ItemID 有明确采购计划比例时，“建议备货 / 可用库存”展示预填数量。点“修改”可查看计划权重、每箱件数及尾差提示，人工可改数量；所有同源候选共享库存，不能把每行可用量相加。
3. 缺少可靠比例时显示待填写；一个计划关联多个 ItemID 且没有分项数量时不自动等分。缺少唯一箱规时按件数建议并提示未按箱规取整。建议为 0 时须人工确认正数量后才能提交。
4. “到货情况”依次显示采购量／累计已到量／未到量，并显示部分到货、全部到货、未到货或未知。已到取领星采购明细 quantity_entry，未到取 quantity_receive；空值不是零，也不靠采购减待到反推已到。已到量不是当前库存。多个 ItemID 行会重复展示采购计数，不可跨行累加。
5. “分批到货”独立筛选已观测分批、单批已到齐和未知；分批可以已经全部到货。批次序号仅基于当前发布范围，历史覆盖不足时保留未知。
6. 更换目标店铺或 ItemID 后重新核对数量；原比例建议仅供参考。可选目标仍为同账号同 SKU 全店铺范围，但必须满足 WFS 转换完成、GTIN、MSKU 及库存校验。
7. 审批继续保存 PostgreSQL 订单、库存分配、审批快照和审计事件。历史记录不按最新备注重算。本轮未增加旧领星人工单迁移、OWS 回填、领星建单或 Walmart 写入。

完整字段及接口：[WFS、比例与到货接口补充](../api/pmc-domestic-packing-approval-allocation-arrival-api.md)。

## 以下为早期操作与实施记录

2026-10-21，当前dev，本地127.0.0.1:55432/LOCAL_DATABASE_NAME。最终范围是手工添加打包单与审批前同SKU商品身份修改；系统打包单管理已按负责人要求删除。没有生产访问、提交、推送或部署。

流程：先选择当前批次看板的入库单×SKU，再选择同账号同SKU的有效Listing目标店铺/ItemID；GTIN/MSKU跟随Listing，不能自由修改SKU。填写数量、报关和原因后，仅保存待审批申请，不发PK、不分配库存。手工添加和修改都不填写收货仓、姓名、口令；收货仓沿用已发布批次仓库名称。通过审批时重新核对当前来源和Listing指纹、库存上限，并在单事务中发PK、分配原来源库存和写不可变审计；驳回需要原因、姓名和口令。多个手工申请共用原入库库存池，可分批审批但不可超量。

跨店铺以当前批次看板入库单为依据，保存原始和目标快照，不要求不存在的领星审批/转移单，不修改领星库存归属。缺少报关信息默认不报关并标记default；人工选择标记manual。未知到货数量保持未知。表格第二列展示草稿号，来自采购看板同一采购单和 SKU，没有则显示破折号。全部审批仍受local-only/is_test保护，不创建领星OWS或调用WFS。

手工新增需独立packing-manual-create动作权限；页面只读权限不能提交。既有approve/reject动作和来源账号隔离继续生效，不自动授予角色或用户权限。

1. 登录后进入PMC→国内仓看板→打包单审批，点“手工添加打包单”。
2. 先搜索并选择入库单×SKU，核对可用量；无可用量来源不可选。
3. 选择同SKU目标店铺/ItemID，核对自动带出的GTIN/MSKU；跨店铺保留原入库库存依据。
4. 填数量、报关和添加原因，提交后在待审批列表查找“手工待审批（未发PK）”。不填写收货仓、姓名、口令。
5. 修改时核对身份、数量及标签；不填写收货仓、姓名和口令。身份变化须写原因。通过后才生成PK并占用库存。驳回须原因、姓名和口令。
6. 审批记录查看原始/最终快照及审计；网络重试复用幂等键，冲突时刷新后核对，不重复占用。
7. 手工按钮禁用时检查manual-create动作权限；不自动修改角色授权。

当前不含系统打包单管理、OWS关联、作废、业务测试切换、仓库装箱、领星自动建单或生产开放。

## 2026-10-21 报关与操作列最终调整

下拉仅有“报关”和“不报关”，列表、手工添加、审批弹窗一致，没有可选“默认规则”。初次显示服务端自动结果，未修改时内部命令仍为default，并非前端第三个选项；用户选择后命令declare/skip，结果标记manual，随审批保存，列表暂存不直接写库。

优先产品purchase_remark（当前DWD产品快照所指原始成功响应，按商品ID精确匹配）。字段存在但为空视为无明确备注，默认false；字段不可用时回退同账号同SKU当前DWD所指ODS采购计划/采购明细item_purchase_remark/remark/plan_remark。否定词优先。采购兜底最新明确不报关优先，否则任一历史当前单据明确报关则报关，否则默认false。单据只读取DWD当前版本所指ODS，不能累加同一单据历史旧版本；拆分采购行去重。

既有MART payload新增customs_proof：value(bool)、source(default/product_remark/purchase_remark)、rule(domestic.customs.v1)、field、remark(最多500字)、ref(来源RAW引用或ODS记录UUID)、observed_at。Candidate映射customs_default、customs_default_src与customs_proof，来源证据进入candidate_version；default命令由后端取当前自动结果，人工选择记manual。订单现有customs_value/customs_src及JSON快照/不可变事件保存审批结果，不覆盖历史。旧无证据快照兼容默认false，不追写历史审批。

数据整理在既有发布流程完成，正常业务GET不访问RAW/ODS、不调用领星；CSV不带该新增数据库备注证据，不能声称CSV和本次备注富化字段相同。未改库存、商品身份和到仓日期。

本地备份后重建当前1454行发布版本，其中155行产品采购备注判定报关，1299行默认不报关；旧发布版本保留，MART历史总4362。迁移仍0052，无新表/字段/约束、无0053，历史4审批/3分配/4事件和用户29保留。

操作列“修改”普通按钮、“审批通过”蓝色主按钮、“驳回”普通按钮，统一间距和最小280px列宽（兼容已有窄列设置），权限/业务阻断逻辑不变。当前仅进行本地本模块验证，不进行全局测试；全局回归待用户后续功能全部完成后统一安排。


> 占位名称说明：`LOCAL_DATABASE_NAME` 与 `ISOLATED_TEST_DATABASE_NAME` 分别表示负责人已批准的本地开发库和隔离测试库；执行前必须与获批本地配置中的实际数据库名逐字核对，并同时核对环境、host、port及连接后数据库身份。占位名称不是可直接执行的数据库名，也不授权其他本地库或生产库。历史数量、指纹及备份哈希保持原记录。
