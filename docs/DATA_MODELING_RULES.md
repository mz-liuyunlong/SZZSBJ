# 数据建模规则

## 文件用途

本文件用于约束业务数据模型如何设计，避免平台 ID、内部 ID、SKU、MSKU、金额、时间混乱。

## 核心原则

1. 系统内部 ID 与平台 ID 必须分开。
2. SKU / MSKU / Item ID 必须明确定义。
3. 所有业务数据通常需要店铺维度。
4. 金额字段必须带币种后缀。
5. 时间字段必须明确业务含义。
6. 外部平台原始数据与系统标准化数据应分层。
7. 任务表、操作日志表、同步批次表应作为基础模型。

## 常见字段建议

| 场景 | 字段示例 | 说明 |
|---|---|---|
| 内部主键 | `id` | 系统内部 ID |
| 平台 ID | `platform_order_id` | 平台订单号 |
| 店铺 | `store_id` | 店铺维度 |
| 金额 | `settlement_amount_usd` | 明确币种 |
| 时间 | `ordered_at` | 业务时间 |
| 同步 | `sync_batch_id` | 同步批次 |
| 原始数据 | `raw_payload` | 仅必要时保留 |

## 禁止

AI 不允许把所有平台字段直接无脑塞进一张大表，也不允许因为字段暂时不清楚就使用 `data1`、`data2` 这类名称。
