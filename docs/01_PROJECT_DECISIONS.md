# 本项目 项目决策日志

## D-001：新系统采用旁路重建，不改旧系统

- 日期：2026-09-01
- 决策：新系统从零开始搭建，旧系统放入 `old-system/` 只读参考。
- 原因：旧系统生产依赖复杂，直接重构风险高。
- 影响：AI 不允许修改、格式化、运行、复制 old-system 代码。

---

## D-002：数据库选择 PostgreSQL

- 日期：2026-09-01
- 决策：本项目 新库使用 PostgreSQL。
- 原因：适合企业后台、关系建模、JSONB 配置、审计、权限、数据中台和后续云托管。
- 影响：新系统迁移只允许 Alembic，不允许手工 SQL 直跑生产。

---

## D-003：旧库 MySQL 只读接入

- 日期：2026-09-01
- 决策：旧系统 MySQL 作为 legacy data source，只读接入。
- 原因：旧库包含历史原始数据和已存在同步链路，不应在第一阶段复制或改写。
- 影响：新系统第一阶段通过只读 API / Repository 查询旧库，不写旧库。

---

## D-004：不新增第二套后台管理系统

- 日期：2026-09-01
- 决策：不创建独立 admin-app / admin-frontend / management-system。
- 原因：避免两套登录、两套权限、两套菜单、两套维护成本。
- 影响：管理功能放入现有 `设置` 与 `数据中心`。

---

## D-005：API 文档放在数据中心

- 日期：2026-09-01
- 决策：API 文档固定放在 `数据中心 > API文档`。
- 原因：API 文档不是普通用户功能，只给开发、管理员、维护人员查看。
- 权限点：`data_center.api_docs.view`。

---

## D-006：页面帮助固定右上角小问号

- 日期：2026-09-01
- 决策：每个页面右上角固定 `? 帮助`，点击新标签页打开对应 SOP。
- 原因：用户在使用页面时直接查看说明，比单独找文档更方便。
- 影响：每个页面配置必须包含 `help.helpUrl`。

---

## D-007：角色不写死，权限页面配置

- 日期：2026-09-01
- 决策：系统不内置固定业务角色，超级管理员在页面上配置角色和权限。
- 原因：公司组织和职责会变化，写死角色会限制后续管理。
- 影响：代码只判断 `permissionKey`，禁止判断 `roleName`。

---

## D-008：每个页面支持独立数据权限

- 日期：2026-09-01
- 决策：页面权限和数据权限分开。每个页面可以配置全部数据、自己的数据、小组数据、指定数据等。
- 原因：运营、组长、主管、老板的数据范围不同。
- 影响：后端必须强制执行数据过滤。

---

## D-009：引入组织架构和产品负责人归属

- 日期：2026-09-01
- 决策：支持部门、小组、组长、组员、直属关系；产品/SKU 负责人独立维护。
- 原因：小组长需要看组员产品，主管需要看部门产品。
- 影响：数据权限可基于 `own`、`direct_reports`、`team`、`org_tree` 计算。

---

## D-010：费用规则必须版本化

- 日期：2026-09-01
- 决策：店铺佣金、平台费、汇率、成本等规则必须有生效日期和版本。
- 原因：不能因为今天调整佣金比例而改乱历史利润。
- 影响：费用规则禁止覆盖历史，只能新增版本。

---

## D-011：AI Token / 飞书 Webhook 页面管理但不明文展示

- 日期：2026-09-01
- 决策：集成配置放在 `设置 > 系统配置 > 集成配置`。
- 原因：需要页面管理 AI Token、飞书群、Webhook、外部 API，但必须安全。
- 影响：密钥加密存储，页面只显示脱敏值，所有变更审计。
